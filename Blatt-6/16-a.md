# Übungsblatt 06, Aufgabe 16(a): DNS Master-Zonen mit BIND9

## Kontext

In Aufgabe 16(a) mussten auf `pcsec1` und auf `dns` die BIND9-Pakete installiert und zwei DNS-Zonen als Master-Zonen eingerichtet werden.

Für Gruppe 09 wurden folgende Zonen umgesetzt:

| Zone | Netz | Master |
|---|---:|---|
| `gruppe09.secp-int.lab.nm.ifi.lmu.de` | `10.153.210.193/26` | `dns` |
| `sub09.gruppe09.secp-int.lab.nm.ifi.lmu.de` | `10.153.210.0/29` | `pcsec1` |

Zusätzlich sollte `pcsec1` DNS-Anfragen nur auf `ens7` und Loopback annehmen. Das Management-Interface `ens2` mit `2001:db6::3` durfte nicht antworten.

---

## 1. Netzwerk und Paketinstallation auf pcsec1 reparieren

Zuerst funktionierte `apt` auf `pcsec1` nicht, weil keine funktionierende Route und keine funktionierende DNS-Auflösung vorhanden waren. Es gab Fehler wie:

```text
Temporary failure resolving 'archive.debian.org'
```

Außerdem zeigte `ip route` nur eine alte OpenVPN-Route über `tun0`.

Alte VPN-Reste wurden entfernt:

```bash
systemctl stop openvpn@secp 2>/dev/null || true
ip link delete tun0 2>/dev/null || true
ip xfrm policy flush
ip xfrm state flush
```

Danach wurde `ens7` auf `pcsec1` wieder gesetzt:

```bash
ip link set ens7 up
ip addr flush dev ens7
ip addr add 10.153.210.2/29 dev ens7
ip route add default via 10.153.210.1 dev ens7
```

Prüfung:

```bash
ip addr show ens7
ip route
ping -c 2 10.153.210.1
```

Erwartete Route:

```text
default via 10.153.210.1 dev ens7
10.153.210.0/29 dev ens7 proto kernel scope link src 10.153.210.2
```

Da IPv4-Internet nicht direkt verfügbar war, wurde IPv6 über `gwsec` verwendet. `gwsec` hatte `2001:db6::2`, `pcsec1` hatte `2001:db6::3`.

Auf `pcsec1`:

```bash
ip -6 route add default via 2001:db6::2 dev ens2
cat > /etc/resolv.conf <<'EOF'
nameserver 2001:4ca0:0:100:0:53:64:1
EOF
```

Test:

```bash
ping6 -c 2 2001:4ca0:0:100:0:53:64:1
getent hosts archive.debian.org
```

Damit funktionierte die Namensauflösung wieder.

---

## 2. BIND9 auf pcsec1 installieren

Auf `pcsec1`:

```bash
apt update
apt install -y bind9 bind9utils dnsutils
systemctl enable bind9
systemctl start bind9
systemctl status bind9 --no-pager
```

Der Dienst lief danach:

```text
Active: active (running)
```

## 3. Subzone auf pcsec1 als Master konfigurieren

Datei:

```bash
/etc/bind/named.conf.local
```

Inhalt:

```conf
zone "sub09.gruppe09.secp-int.lab.nm.ifi.lmu.de" {
    type master;
    file "/etc/bind/db.sub09.gruppe09.secp-int.lab.nm.ifi.lmu.de";
};
```

## 5. pcsec1 nur auf ens7 und Loopback lauschen lassen

BIND lauscht nicht direkt auf Interface-Namen, sondern auf IP-Adressen. Deshalb wurde `pcsec1` so konfiguriert, dass nur `127.0.0.1`, `10.153.210.2` und `::1` verwendet werden.

Datei:

```bash
/etc/bind/named.conf.options
```

Inhalt:

```conf
options {
    directory "/var/cache/bind";

    listen-on {
        127.0.0.1;
        10.153.210.2;
    };

    listen-on-v6 {
        ::1;
    };

    allow-query { any; };

    recursion no;
    dnssec-validation no;

    auth-nxdomain no;
};
```

Dadurch antwortet `pcsec1` nicht auf dem Management-Interface `2001:db6::3`.

## 7. Host dns finden

Der Host `dns` war zunächst nicht per Name erreichbar. Deshalb wurde im Servernetz gesucht.

Auf `gwsec`:

```bash
ip link set ens8 up
ip addr add 10.153.210.193/26 dev ens8 2>/dev/null || true

for i in $(seq 193 254); do
  ping -I ens8 -c1 -W1 10.153.210.$i >/dev/null 2>&1 && echo "alive: 10.153.210.$i"
done
```

Gefunden:

```text
alive: 10.153.210.251
alive: 10.153.210.254
```

Login auf `10.153.210.251` ergab:

```bash
hostname
```

Ergebnis:

```text
dns
```

Damit:

```text
dns IPv4 = 10.153.210.251
dns IPv6 = 2001:4ca0:4001:f00::251
```

`10.153.210.254` wurde als `secserver` verwendet, weil der Host auf Ping antwortete, aber SSH geschlossen war.
