# Blatt 3, Aufgabe 9a: Firewall-Konfiguration prüfen

## Ziel der Aufgabe

In Aufgabe 9a soll geprüft werden, dass keine standardmäßig eingerichtete Firewall-Konfiguration der Distribution aktiv ist. Danach sollen die Regeln aller iptables-Ketten angezeigt werden.

Die Aufgabe ist eher eine kurze Vorbereitungsaufgabe für die späteren Firewall-Regeln. Wichtig ist, dass der Ausgangszustand sauber ist: keine aktive Standard-Firewall und keine bereits gesetzten Paketfilterregeln.

## 1. Prüfen, ob Standard-Firewall-Dienste aktiv sind

Zuerst wurden typische Firewall-Dienste geprüft:

```bash
systemctl status ufw
systemctl status firewalld
systemctl status nftables
```

Bei uns kam jeweils:

```bash
Unit ufw.service could not be found.
Unit firewalld.service could not be found.
Unit nftables.service could not be found.
```

Das bedeutet: Diese Firewall-Dienste sind auf dem System nicht vorhanden bzw. nicht aktiv.

## 2. iptables war zuerst nicht installiert

Beim ersten Aufruf von `iptables` kam:

```bash
iptables: command not found
```

Deshalb musste `iptables` nachinstalliert werden:

```bash
apt update
apt install -y iptables
```

Danach war der Befehl verfügbar.

## 3. Regeln der Filter-Tabelle anzeigen

Die normale Filter-Tabelle wurde mit folgendem Befehl angezeigt:

```bash
iptables -L -n -v
```

Ergebnis:

```bash
Chain INPUT (policy ACCEPT 0 packets, 0 bytes)
 pkts bytes target     prot opt in     out     source               destination         

Chain FORWARD (policy ACCEPT 0 packets, 0 bytes)
 pkts bytes target     prot opt in     out     source               destination         

Chain OUTPUT (policy ACCEPT 0 packets, 0 bytes)
 pkts bytes target     prot opt in     out     source               destination
```

Bedeutung:

- `INPUT`: Pakete, die an den Rechner selbst gehen
- `FORWARD`: Pakete, die durch den Rechner weitergeleitet werden
- `OUTPUT`: Pakete, die vom Rechner selbst ausgehen
- `policy ACCEPT`: Standardmäßig werden Pakete akzeptiert
- Keine Einträge unter `target`: Es sind keine zusätzlichen Regeln aktiv

## 4. Regeln der NAT-Tabelle anzeigen

Die NAT-Tabelle wurde mit folgendem Befehl angezeigt:

```bash
iptables -t nat -L -n -v
```

Ergebnis:

```bash
Chain PREROUTING (policy ACCEPT 0 packets, 0 bytes)
Chain INPUT (policy ACCEPT 0 packets, 0 bytes)
Chain OUTPUT (policy ACCEPT 0 packets, 0 bytes)
Chain POSTROUTING (policy ACCEPT 0 packets, 0 bytes)
```

Bedeutung:

- `PREROUTING`: Bearbeitung vor Routing-Entscheidung
- `INPUT`: NAT-Regeln für Pakete an den lokalen Rechner
- `OUTPUT`: NAT-Regeln für lokal erzeugte Pakete
- `POSTROUTING`: Bearbeitung nach Routing-Entscheidung
- Auch hier sind keine zusätzlichen Regeln aktiv

## 5. Regeln der Mangle-Tabelle anzeigen

Die Mangle-Tabelle wurde mit folgendem Befehl angezeigt:

```bash
iptables -t mangle -L -n -v
```

Ergebnis:

```bash
Chain PREROUTING (policy ACCEPT 0 packets, 0 bytes)
Chain INPUT (policy ACCEPT 0 packets, 0 bytes)
Chain FORWARD (policy ACCEPT 0 packets, 0 bytes)
Chain OUTPUT (policy ACCEPT 0 packets, 0 bytes)
Chain POSTROUTING (policy ACCEPT 0 packets, 0 bytes)
```

Bedeutung:

Die Mangle-Tabelle wird genutzt, um Pakete speziell zu verändern oder zu markieren. Für diese Aufgabe ist wichtig, dass auch dort keine Regeln gesetzt sind.

## 6. IPv6-Regeln prüfen

Zusätzlich wurden auch die IPv6-Regeln geprüft:

```bash
ip6tables -L -n -v
ip6tables -t mangle -L -n -v
```

Auch hier waren alle Ketten leer und die Default-Policies standen auf `ACCEPT`.

## 7. Hinweis zur Locale-Warnung

Während der Installation kam eine Warnung wie:

```bash
locale: Cannot set LC_ALL to default locale: No such file or directory
```

Diese Warnung ist für Aufgabe 9a nicht relevant. Sie betrifft nur die Spracheinstellungen des Systems und nicht die Firewall.

## Ergebnis

Die Aufgabe 9a ist erfüllt:

- `ufw` ist nicht aktiv bzw. nicht vorhanden
- `firewalld` ist nicht aktiv bzw. nicht vorhanden
- `nftables` ist nicht aktiv bzw. nicht vorhanden
- `iptables` wurde nachinstalliert
- Die Regeln aller wichtigen Ketten wurden angezeigt
- Die Filter-, NAT- und Mangle-Tabellen enthalten keine zusätzlichen Regeln
- Die Default-Policies stehen auf `ACCEPT`
- Auch IPv6 wurde mit `ip6tables` geprüft

## Kurzer Abgabetext

```text
Auf dem System waren keine standardmäßigen Firewall-Dienste aktiv. Die Dienste ufw, firewalld und nftables waren nicht vorhanden. Da iptables zunächst nicht installiert war, wurde das Paket iptables nachinstalliert.

Anschließend wurden die Regeln aller Ketten mit iptables angezeigt. Die Filter-, NAT- und Mangle-Tabellen enthalten keine zusätzlichen Regeln. Alle Default-Policies stehen auf ACCEPT. Auch die IPv6-Regeln wurden mit ip6tables geprüft und enthalten keine zusätzlichen Regeln.
```
