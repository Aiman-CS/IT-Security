# Blatt 3, Aufgabe 9f: Firewall beim Start vor den Netzwerkkarten aktivieren

## Aufgabenstellung

In Aufgabe 9f soll der Rechner so eingerichtet werden, dass die Firewall beim Start automatisch aktiviert wird, und zwar noch bevor die Netzwerkkarten aktiv werden.

Ziel ist, dass der Rechner nicht kurzzeitig ohne Firewall-Regeln im Netz erreichbar ist.

## Ausgangspunkt

Die Firewall aus Aufgabe 9d liegt bereits auf `pcsec1` unter:

```bash
/home/secpgast/Abgaben/9/9d-firewall
```

Dieses Script lädt die statische IPv4-Firewall für `pcsec1`.

Für Aufgabe 9f wurde ein `systemd`-Service erstellt, der dieses Firewall-Script beim Booten automatisch ausführt.

## 1. Service-Datei erstellen

Auf `pcsec1` wurde folgende Service-Datei erstellt:

```bash
cat > /etc/systemd/system/pcsec1-firewall.service <<'EOF'
[Unit]
Description=Aufgabe 9d IPv4 Firewall fuer pcsec1
DefaultDependencies=no
Wants=network-pre.target
Before=network-pre.target networking.service network.target
After=local-fs.target

[Service]
Type=oneshot
ExecStart=/home/secpgast/Abgaben/9/9d-firewall
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
```

Die Datei liegt danach unter:

```bash
/etc/systemd/system/pcsec1-firewall.service
```

## 2. Erklärung der Service-Datei

### `[Unit]`

```ini
[Unit]
Description=Aufgabe 9d IPv4 Firewall fuer pcsec1
```

Die Beschreibung zeigt an, wofür der Service verwendet wird.

```ini
DefaultDependencies=no
```

Damit werden die normalen Standard-Abhängigkeiten von `systemd` deaktiviert. Das ist wichtig, damit der Service sehr früh im Bootprozess gestartet werden kann.

```ini
Wants=network-pre.target
```

Damit wird `network-pre.target` in den Bootprozess einbezogen. Dieses Target ist für Dienste gedacht, die vor der Netzwerkkonfiguration laufen sollen.

```ini
Before=network-pre.target networking.service network.target
```

Damit wird festgelegt, dass dieser Service vor der Netzwerkkonfiguration gestartet werden soll.

Das bedeutet:

- vor `network-pre.target`
- vor `networking.service`
- vor `network.target`

Dadurch sollen die Firewall-Regeln geladen werden, bevor die Netzwerkkarten vollständig aktiv sind.

```ini
After=local-fs.target
```

Damit wird sichergestellt, dass lokale Dateisysteme verfügbar sind, bevor das Firewall-Script ausgeführt wird. Das ist nötig, weil das Script unter `/home/secpgast/Abgaben/9/9d-firewall` liegt.

### `[Service]`

```ini
Type=oneshot
```

Der Service führt nur einmal ein Script aus und beendet sich danach. Das passt zu einer Firewall-Konfiguration, weil `iptables`-Regeln im Kernel gesetzt werden und danach kein dauerhaft laufender Prozess nötig ist.

```ini
ExecStart=/home/secpgast/Abgaben/9/9d-firewall
```

Hier wird das Firewall-Script aus Aufgabe 9d ausgeführt.

Wichtig: Es wird nicht das Reset-Script verwendet, sondern das Firewall-Script aus 9d.

```ini
RemainAfterExit=yes
```

Damit bleibt der Service nach erfolgreicher Ausführung als aktiv markiert, obwohl das Script bereits beendet ist.

### `[Install]`

```ini
WantedBy=multi-user.target
```

Damit wird der Service beim normalen Systemstart aktiviert.

## 3. systemd neu laden

Nach dem Erstellen oder Ändern der Service-Datei wurde `systemd` neu geladen:

```bash
systemctl daemon-reload
```

Dieser Befehl sorgt dafür, dass `systemd` die neue oder geänderte Service-Datei einliest.

## 4. Service dauerhaft aktivieren

Der Service wurde aktiviert:

```bash
systemctl enable pcsec1-firewall.service
```

Damit wird der Service beim Systemstart automatisch gestartet.

## 5. Service starten bzw. neu starten

Der Service wurde danach gestartet bzw. neu gestartet:

```bash
systemctl restart pcsec1-firewall.service
```

Dadurch wurde das Firewall-Script direkt ausgeführt, ohne auf einen Reboot warten zu müssen.

Der Status wurde geprüft:

```bash
systemctl status pcsec1-firewall.service
```

Ergebnis:


## 7. Erklärung des Status

Wichtige Zeilen:

```text
Loaded: loaded (...; enabled; ...)
```

Der Service wurde gefunden und ist dauerhaft aktiviert.

```text
Active: active (exited)
```

Das ist bei einem `oneshot`-Service korrekt. Das Script wurde ausgeführt und danach beendet. Durch `RemainAfterExit=yes` bleibt der Service als aktiv markiert.

```text
ExecStart=/home/secpgast/Abgaben/9/9d-firewall (code=exited, status=0/SUCCESS)
```

Das Firewall-Script wurde erfolgreich ausgeführt.

```text
Statische IPv4-Firewall fuer Aufgabe 9d wurde geladen.
```

Diese Ausgabe kommt direkt aus dem Firewall-Script und zeigt, dass die Firewall-Konfiguration geladen wurde.

## 8. Prüfen, ob der Service aktiviert ist

Der Service wurde mit folgendem Befehl geprüft:

```bash
systemctl is-enabled pcsec1-firewall.service
```

Ergebnis:

```text
enabled
```

Das bedeutet, dass der Service beim Systemstart automatisch gestartet wird.

## 9. Firewall-Regeln prüfen

Nach dem Start des Services wurden die Firewall-Regeln geprüft:

```bash
iptables -L -n -v --line-numbers
```

Die Ausgabe zeigte, dass die Regeln aus Aufgabe 9d geladen wurden.

Wichtige Punkte:

```text
Chain INPUT (policy DROP)
Chain FORWARD (policy DROP)
Chain OUTPUT (policy DROP)
```

Damit sind die Default-Policies aktiv und blockieren alles, was nicht explizit erlaubt wurde.

Außerdem waren die Regeln für die geforderten Dienste sichtbar:

- FTP, TCP Port 20 und 21
- SSH, TCP Port 22 mit Logging
- SMTP, TCP Port 25 mit Logging
- DNS, UDP Port 53 mit Logging
- NTP, UDP Port 123 ohne Logging
- Telnet, TCP Port 23 nur zwischen `pcsec1` und `pcsec2`
- FORWARD-Regeln für die weiterzuleitenden Dienste

## 10. Ergebnis

Auf `pcsec1` wurde ein `systemd`-Service eingerichtet, der beim Systemstart automatisch das Firewall-Script aus Aufgabe 9d ausführt.

Der Service ist aktiviert:

```text
enabled
```

Der Service wurde erfolgreich gestartet:

```text
active (exited)
status=0/SUCCESS
```

Die Firewall-Regeln wurden danach erfolgreich geladen und mit `iptables -L -n -v --line-numbers` überprüft.

Damit ist Aufgabe 9f erfüllt.
