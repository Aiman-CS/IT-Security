# Blatt 3, Aufgabe 10b: Ungewünschte Funktionalität bei NAT (Theorieaufgabe)

## Fragestellung

Welche unter Umständen nicht gewünschte Funktionalität wird für NAT benötigt? Wie kann man das Problem umgehen?

## Antwort

### Das Problem: IP-Forwarding

Damit NAT funktioniert, muss auf dem Router **IP-Forwarding** aktiviert werden:

```bash
echo 1 > /proc/sys/net/ipv4/ip_forward
```

Ohne IP-Forwarding verwirft der Linux-Kernel alle Pakete, die nicht an den Rechner selbst adressiert sind. NAT braucht aber genau diese Weiterleitung, weil der Router Pakete von einem Interface (ens7, internes Netz) zum anderen (ens8, externes Netz) durchreichen muss.

### Warum ist das problematisch?

Wenn IP-Forwarding aktiviert ist, leitet der Rechner **alle** Pakete zwischen seinen Interfaces weiter – nicht nur die, für die NAT konfiguriert ist. Das bedeutet:

- Jeder Host im internen Netz könnte Pakete über den Router ins externe Netz schicken
- Der Router wird zu einem offenen Gateway für alle Geräte
- Es gibt keine Kontrolle darüber, welcher Traffic durchgelassen wird
- Das ist ein **Sicherheitsrisiko**, weil ungewollter Verkehr durchgelassen werden könnte

### Lösung: FORWARD-Chain mit DROP-Policy

Man kann das Problem umgehen, indem man die **FORWARD-Chain** der iptables-Firewall mit einer Default-Policy `DROP` konfiguriert und nur den gewünschten Traffic explizit erlaubt:

```bash
# Default: Alles verwerfen
iptables -P FORWARD DROP

# Nur pcsec2 <-> dns4all erlauben
iptables -A FORWARD -s 10.153.210.3 -d 10.153.210.251 -i ens7 -o ens8 -j ACCEPT
iptables -A FORWARD -s 10.153.210.251 -d 10.153.210.3 -i ens8 -o ens7 -j ACCEPT
```

So ist IP-Forwarding zwar aktiv (Kernel leitet Pakete weiter), aber die Firewall filtert auf der FORWARD-Chain und lässt nur die explizit erlaubten Verbindungen durch. Alle anderen Pakete werden verworfen.

Das wurde in Aufgabe 10a genau so umgesetzt: IP-Forwarding ist aktiviert, aber die FORWARD-Policy ist DROP und nur pcsec2 ↔ dns4all ist erlaubt.

## Zusammenfassung

| | |
|---|---|
| **Benötigte Funktionalität** | IP-Forwarding (`ip_forward = 1`) |
| **Problem** | Router leitet alle Pakete weiter, nicht nur NAT-Traffic |
| **Lösung** | FORWARD-Chain mit Policy DROP + explizite ACCEPT-Regeln nur für gewünschten Traffic |
