# Blatt 3, Aufgabe 10a: NAT/PAT für pcsec2 beim Zugriff auf dns4all über IPv4

## Aufgabenstellung

In Aufgabe 10a soll auf dem Router `gwsec` eine NAT/PAT-Konfiguration erstellt werden, die **ausschließlich für pcsec2** eine Adressübersetzung durchführt, wenn pcsec2 über IPv4 auf `dns4all` zugreift.

Das Script muss unter folgendem Pfad auf gwsec liegen:

```bash
/home/secpgast/Abgaben/10/a-nat
```

## Was ist NAT/PAT und warum braucht man es hier?

### Das Problem

`pcsec2` hat die IPv4-Adresse `10.153.210.3/29` im internen Netz (ens7). Dieses Netz ist ein privates Subnetz hinter dem Router `gwsec`. Wenn pcsec2 ein Paket an `dns4all` (10.153.210.251) schickt, kommt das Paket zwar über gwsec nach draußen, aber dns4all weiß nicht, wohin die Antwort schicken soll – denn `10.153.210.3` ist aus dem externen Netz nicht direkt erreichbar.

### Die Lösung: NAT/PAT (Network Address Translation / Port Address Translation)

Der Router `gwsec` ersetzt die Quelladresse des Pakets von pcsec2 (`10.153.210.3`) durch seine eigene externe IP (`10.153.210.193` auf ens8). Für dns4all sieht es so aus, als käme das Paket direkt von gwsec. Die Antwort geht dann zurück an gwsec, und gwsec leitet sie an pcsec2 weiter.

Bei **PAT** (Port Address Translation) wird zusätzlich der Quellport verändert, damit gwsec mehrere Verbindungen gleichzeitig auseinanderhalten kann.

In Linux wird das mit `iptables` und der `MASQUERADE`-Regel umgesetzt.

## Netzwerk-Topologie

```text
pcsec2 (10.153.210.3)  ──ens7──  gwsec  ──ens8──  dns4all (10.153.210.251)
        internes Netz              Router            externes Netz
        10.153.210.0/29                               10.153.210.192/26
```

### gwsec (Router)

| Interface | IPv4-Adresse | Netz |
|---|---|---|
| ens7 | 10.153.210.1/29 | internes LAN (pcsec1, pcsec2) |
| ens8 | 10.153.210.193/26 | externes Netz (dns4all, defaultgw) |

### pcsec2

| Interface | IPv4-Adresse |
|---|---|
| ens7 | 10.153.210.3/29 |

### dns4all

| Hostname | IPv4-Adresse |
|---|---|
| test4all.secp.lab.nm.ifi.lmu.de | 10.153.210.251 |

**Hinweis:** Der Name `dns4all` konnte per DNS nicht aufgelöst werden (`dig dns4all A` → NXDOMAIN). Über `nmap -sn 10.153.210.192/26` wurde der Host `test4all.secp.lab.nm.ifi.lmu.de` unter `10.153.210.251` gefunden. Das ist der einzige Server im externen Netz neben dem Gateway (`10.153.210.254`), daher wurde diese IP für dns4all verwendet.

## Das Script

Das Script liegt unter `/home/secpgast/Abgaben/10/a-nat` auf gwsec:

```bash
#!/bin/bash

# Aufgabe 10a - NAT/PAT fuer pcsec2 beim Zugriff auf dns4all ueber IPv4
# Auszufuehren auf gwsec

IPT="/sbin/iptables"

# Interfaces
LAN_IF="ens7"
WAN_IF="ens8"

# IP-Adressen
PCSEC2_IP="10.153.210.3"
DNS4ALL_IP="10.153.210.251"

echo "pcsec2 IPv4:  $PCSEC2_IP"
echo "dns4all IPv4: $DNS4ALL_IP"
echo "LAN_IF:       $LAN_IF"
echo "WAN_IF:       $WAN_IF"

# IPv4-Forwarding aktivieren
echo 1 > /proc/sys/net/ipv4/ip_forward

# Alte NAT-Regeln entfernen
$IPT -t nat -F
$IPT -t nat -X
$IPT -t nat -Z

# FORWARD-Regeln bereinigen
$IPT -F FORWARD
$IPT -P FORWARD DROP

# Forwarding nur fuer pcsec2 <-> dns4all erlauben
$IPT -A FORWARD -s $PCSEC2_IP -d $DNS4ALL_IP -i $LAN_IF -o $WAN_IF -j ACCEPT
$IPT -A FORWARD -s $DNS4ALL_IP -d $PCSEC2_IP -i $WAN_IF -o $LAN_IF -j ACCEPT

# SNAT/MASQUERADE: pcsec2 -> dns4all bekommt die IP von gwsec (ens8)
$IPT -t nat -A POSTROUTING -s $PCSEC2_IP -d $DNS4ALL_IP -o $WAN_IF -j MASQUERADE

echo ""
echo "NAT/PAT fuer pcsec2 -> dns4all wurde eingerichtet."
echo ""
echo "Filter-Regeln:"
$IPT -L FORWARD -v -n --line-numbers
echo ""
echo "NAT-Regeln:"
$IPT -t nat -L -v -n --line-numbers

exit 0
```

## Erklärung des Scripts Zeile für Zeile

### Variablen

```bash
IPT="/sbin/iptables"
```

Pfad zu `iptables`. Wird als Variable gesetzt, damit man es nicht jedes Mal ausschreiben muss.

```bash
LAN_IF="ens7"
WAN_IF="ens8"
```

- `LAN_IF` = Interface Richtung internes Netz (pcsec1, pcsec2)
- `WAN_IF` = Interface Richtung externes Netz (dns4all)

```bash
PCSEC2_IP="10.153.210.3"
DNS4ALL_IP="10.153.210.251"
```

Die IPv4-Adressen von pcsec2 und dns4all, hardcoded weil dns4all per DNS nicht auflösbar ist.

### IPv4-Forwarding aktivieren

```bash
echo 1 > /proc/sys/net/ipv4/ip_forward
```

Aktiviert die Paketweiterleitung im Linux-Kernel. Ohne diese Einstellung verwirft gwsec alle Pakete, die nicht an gwsec selbst adressiert sind. Da gwsec als Router fungieren soll, muss Forwarding aktiv sein.

- `/proc/sys/net/ipv4/ip_forward` ist eine Kernel-Variable
- `1` = aktiviert, `0` = deaktiviert
- Standardmäßig ist Forwarding deaktiviert (Sicherheit)

### NAT-Tabelle bereinigen

```bash
$IPT -t nat -F
$IPT -t nat -X
$IPT -t nat -Z
```

- `-t nat` = arbeitet mit der NAT-Tabelle (nicht der Filter-Tabelle)
- `-F` = **Flush**: Löscht alle Regeln in allen Chains der NAT-Tabelle
- `-X` = **Delete Chain**: Löscht alle benutzerdefinierten Chains
- `-Z` = **Zero**: Setzt alle Paket- und Byte-Zähler auf 0

Das stellt sicher, dass keine alten NAT-Regeln mehr aktiv sind, bevor die neuen gesetzt werden.

### FORWARD-Chain bereinigen und Policy setzen

```bash
$IPT -F FORWARD
$IPT -P FORWARD DROP
```

- `-F FORWARD` = Löscht alle Regeln in der FORWARD-Chain (Filter-Tabelle)
- `-P FORWARD DROP` = Setzt die **Default Policy** auf DROP

Die FORWARD-Chain entscheidet, welche Pakete durch den Router weitergeleitet werden dürfen. Mit `DROP` als Default werden alle Pakete verworfen, die nicht explizit erlaubt sind. Das ist das Prinzip der **Whitelist-Firewall**: Alles ist verboten, nur explizit erlaubte Verbindungen werden durchgelassen.

### FORWARD-Regeln für pcsec2 ↔ dns4all

```bash
$IPT -A FORWARD -s $PCSEC2_IP -d $DNS4ALL_IP -i $LAN_IF -o $WAN_IF -j ACCEPT
```

Erlaubt Pakete **von pcsec2 nach dns4all**:

- `-A FORWARD` = Regel an die FORWARD-Chain anhängen
- `-s 10.153.210.3` = Quelladresse ist pcsec2
- `-d 10.153.210.251` = Zieladresse ist dns4all
- `-i ens7` = Paket kommt rein über das LAN-Interface
- `-o ens8` = Paket geht raus über das WAN-Interface
- `-j ACCEPT` = Paket wird durchgelassen

```bash
$IPT -A FORWARD -s $DNS4ALL_IP -d $PCSEC2_IP -i $WAN_IF -o $LAN_IF -j ACCEPT
```

Erlaubt Pakete **von dns4all zurück an pcsec2** (Antwortpakete):

- `-s 10.153.210.251` = Quelladresse ist dns4all
- `-d 10.153.210.3` = Zieladresse ist pcsec2 (nach dem DNAT durch conntrack)
- `-i ens8` = Paket kommt rein über das WAN-Interface
- `-o ens7` = Paket geht raus über das LAN-Interface

**Wichtig:** Die Aufgabe verlangt NAT/PAT **ausschließlich** für pcsec2. Deshalb werden nur Pakete mit Quelle/Ziel pcsec2 und dns4all erlaubt. Alle anderen Hosts (z.B. pcsec1) können dns4all nicht erreichen, weil die Default Policy DROP ist.

### MASQUERADE-Regel (die eigentliche NAT/PAT-Regel)

```bash
$IPT -t nat -A POSTROUTING -s $PCSEC2_IP -d $DNS4ALL_IP -o $WAN_IF -j MASQUERADE
```

Das ist die zentrale NAT-Regel:

- `-t nat` = NAT-Tabelle
- `-A POSTROUTING` = Regel wird in die POSTROUTING-Chain eingefügt. Diese Chain wird durchlaufen **nachdem** die Routing-Entscheidung getroffen wurde, also kurz bevor das Paket das Interface verlässt
- `-s 10.153.210.3` = nur Pakete von pcsec2
- `-d 10.153.210.251` = nur Pakete an dns4all
- `-o ens8` = nur wenn das Paket über ens8 rausgeht
- `-j MASQUERADE` = ersetzt die Quelladresse des Pakets durch die IP des ausgehenden Interfaces (10.153.210.193)

**MASQUERADE vs. SNAT:**

- `MASQUERADE` ermittelt die Quell-IP dynamisch vom ausgehenden Interface. Vorteil: Funktioniert auch wenn sich die IP von ens8 ändern sollte.
- `SNAT --to-source 10.153.210.193` würde die IP statisch setzen. Ist minimal schneller, aber weniger flexibel.

Für diese Aufgabe funktioniert beides, MASQUERADE ist aber die üblichere Variante.

### Status-Ausgabe

```bash
$IPT -L FORWARD -v -n --line-numbers
$IPT -t nat -L -v -n --line-numbers
```

- `-L FORWARD` = Zeigt die Regeln der FORWARD-Chain
- `-t nat -L` = Zeigt alle Regeln der NAT-Tabelle
- `-v` = Verbose: Zeigt Paketzähler, Interfaces usw.
- `-n` = Numerisch: Löst keine Hostnamen auf (schneller)
- `--line-numbers` = Zeigt die Regelnummer an
