# Blatt 3, Aufgabe 10c: Statische Firewall auf dynamische Paketfilterung umstellen

## Aufgabenstellung

Das statische Regelwerk aus Aufgabe 9d soll auf **dynamische Paketfilterung** umgestellt werden. Die Funktionsweise der Firewall soll sich dabei nicht ändern. Das neue Script liegt auf `pcsec1` unter:

```bash
/home/secpgast/Abgaben/10/c-firewall
```

## Was ändert sich: Statisch vs. Dynamisch

### Statische Firewall (9d)

Bei der statischen Firewall mussten für jeden Dienst **beide Richtungen** explizit erlaubt werden:

```bash
# SSH eingehend
$IPT -A INPUT -p tcp --dport 22 -j ACCEPT
# SSH Antworten (von Port 22 zurück)
$IPT -A INPUT -p tcp --sport 22 -j ACCEPT
```

Das Problem: Die Regel `--sport 22` erlaubt **alle** Pakete mit Quellport 22, auch solche, die zu keiner bestehenden Verbindung gehören. Ein Angreifer könnte ein Paket mit gefälschtem Quellport 22 schicken und es würde durchgelassen.

### Dynamische Firewall (10c) – Connection Tracking

Bei der dynamischen Firewall wird **Connection Tracking** (`conntrack`) verwendet. Der Kernel merkt sich alle bestehenden Verbindungen in einer Tabelle. Dadurch reicht es aus, nur den **Verbindungsaufbau** (NEW) explizit zu erlauben. Alle Antwortpakete werden automatisch über die `ESTABLISHED,RELATED`-Regel durchgelassen:

```bash
# Alle bestehenden Verbindungen erlauben (eine Regel fuer alle Dienste)
$IPT -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# SSH: Nur neue Verbindungen erlauben
$IPT -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT
```

### Vorteile der dynamischen Firewall

| | Statisch (9d) | Dynamisch (10c) |
|---|---|---|
| Antwortpakete | Explizit per `--sport` erlaubt | Automatisch über `ESTABLISHED` |
| Regeln pro Dienst | 2 (dport + sport) | 1 (nur dport mit NEW) |
| Sicherheit | Quellport-Spoofing möglich | Nur echte Antworten erlaubt |
| Gesamtanzahl Regeln | Viele | Deutlich weniger |

## Verbindungsstatus-Erklärung

`-m conntrack --ctstate` prüft den Status einer Verbindung:

| Status | Bedeutung |
|---|---|
| `NEW` | Erstes Paket einer neuen Verbindung (TCP SYN oder erstes UDP-Paket) |
| `ESTABLISHED` | Paket gehört zu einer bereits aufgebauten Verbindung |
| `RELATED` | Paket gehört zu einer verwandten Verbindung (z.B. FTP-Datenverbindung) |
| `INVALID` | Paket kann keiner Verbindung zugeordnet werden |

## Netzwerk-Setup

Vor dem Ausführen musste `ens7` auf pcsec1 hochgefahren und die IPv4-Adresse gesetzt werden:

```bash
ip link set ens7 up
ip addr add 10.153.210.2/29 dev ens7
```

## Das Script

```bash
#!/bin/bash

# Aufgabe 10c - Dynamische IPv4-Firewall fuer pcsec1
# Gleiche Funktionalitaet wie 9d, aber mit Connection Tracking

IPT="/sbin/iptables"

PCSEC1_IP="10.153.210.2"
PCSEC2_IP="10.153.210.3"

# Alle vorhandenen Regeln loeschen
$IPT -F
$IPT -X
$IPT -t nat -F
$IPT -t nat -X
$IPT -t mangle -F
$IPT -t mangle -X

# Default-Policies
$IPT -P INPUT DROP
$IPT -P OUTPUT DROP
$IPT -P FORWARD DROP

# Loopback erlauben
$IPT -A INPUT -i lo -j ACCEPT
$IPT -A OUTPUT -o lo -j ACCEPT

########################################
# Bestehende/verwandte Verbindungen erlauben
########################################

$IPT -A INPUT  -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
$IPT -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
$IPT -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

########################################
# FTP, TCP 20/21, ohne Logging
########################################

$IPT -A INPUT  -p tcp --dport 20 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A OUTPUT -p tcp --dport 20 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A FORWARD -p tcp --dport 20 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A INPUT  -p tcp --dport 21 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A OUTPUT -p tcp --dport 21 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A FORWARD -p tcp --dport 21 -m conntrack --ctstate NEW -j ACCEPT

########################################
# SSH, TCP 22, mit Logging nur Verbindungsaufbau
########################################

$IPT -A INPUT  -p tcp --dport 22 -m conntrack --ctstate NEW -j LOG --log-prefix "SSH-IN-NEW: "
$IPT -A INPUT  -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A OUTPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j LOG --log-prefix "SSH-OUT-NEW: "
$IPT -A OUTPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A FORWARD -p tcp --dport 22 -m conntrack --ctstate NEW -j LOG --log-prefix "SSH-FWD-NEW: "
$IPT -A FORWARD -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT

########################################
# SMTP, TCP 25, mit Logging nur Verbindungsaufbau
########################################

$IPT -A INPUT  -p tcp --dport 25 -m conntrack --ctstate NEW -j LOG --log-prefix "SMTP-IN-NEW: "
$IPT -A INPUT  -p tcp --dport 25 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A OUTPUT -p tcp --dport 25 -m conntrack --ctstate NEW -j LOG --log-prefix "SMTP-OUT-NEW: "
$IPT -A OUTPUT -p tcp --dport 25 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A FORWARD -p tcp --dport 25 -m conntrack --ctstate NEW -j LOG --log-prefix "SMTP-FWD-NEW: "
$IPT -A FORWARD -p tcp --dport 25 -m conntrack --ctstate NEW -j ACCEPT

########################################
# DNS-Abfragen, UDP 53, mit Logging
########################################

$IPT -A INPUT  -p udp --dport 53 -m conntrack --ctstate NEW -j LOG --log-prefix "DNS-IN-QUERY: "
$IPT -A INPUT  -p udp --dport 53 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A OUTPUT -p udp --dport 53 -m conntrack --ctstate NEW -j LOG --log-prefix "DNS-OUT-QUERY: "
$IPT -A OUTPUT -p udp --dport 53 -m conntrack --ctstate NEW -j ACCEPT

$IPT -A FORWARD -p udp --dport 53 -m conntrack --ctstate NEW -j LOG --log-prefix "DNS-FWD-QUERY: "
$IPT -A FORWARD -p udp --dport 53 -m conntrack --ctstate NEW -j ACCEPT

########################################
# NTP-Abfragen, UDP 123, ohne Logging
########################################

$IPT -A INPUT  -p udp --dport 123 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A OUTPUT -p udp --dport 123 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A FORWARD -p udp --dport 123 -m conntrack --ctstate NEW -j ACCEPT

########################################
# Telnet, TCP 23, nur pcsec1 <-> pcsec2
########################################

$IPT -A OUTPUT -p tcp -s $PCSEC1_IP -d $PCSEC2_IP --dport 23 -m conntrack --ctstate NEW -j ACCEPT
$IPT -A INPUT  -p tcp -s $PCSEC2_IP -d $PCSEC1_IP --dport 23 -m conntrack --ctstate NEW -j ACCEPT

echo "Dynamische IPv4-Firewall fuer Aufgabe 10c wurde geladen."
exit 0
```

## Erklärung der wichtigsten Änderungen gegenüber 9d

### 1. ESTABLISHED,RELATED-Regeln (neu)

```bash
$IPT -A INPUT  -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
$IPT -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
$IPT -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

- `-m conntrack` = Lädt das Connection-Tracking-Modul
- `--ctstate ESTABLISHED,RELATED` = Matcht Pakete, die zu einer bestehenden oder verwandten Verbindung gehören
- Diese drei Regeln stehen **ganz oben** (nach Loopback), weil sie für alle Dienste gelten
- Sie ersetzen alle `--sport`-Regeln aus dem statischen Script

### 2. Nur noch `--dport` mit `NEW` statt `--dport` + `--sport`

**Statisch (9d):**
```bash
# SSH eingehend – 2 Regeln nötig
$IPT -A INPUT -p tcp --dport 22 -j ACCEPT
$IPT -A INPUT -p tcp --sport 22 -j ACCEPT
```

**Dynamisch (10c):**
```bash
# SSH eingehend – 1 Regel reicht
$IPT -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT
```

Die `--sport 22`-Regel fällt weg, weil Antwortpakete automatisch über `ESTABLISHED` erlaubt werden.

### 3. Telnet vereinfacht

**Statisch (9d):**
```bash
# pcsec1 -> pcsec2 (Hinrichtung + Rückrichtung)
$IPT -A OUTPUT -p tcp -s $PCSEC1_IP -d $PCSEC2_IP --dport 23 -j ACCEPT
$IPT -A INPUT  -p tcp -s $PCSEC2_IP -d $PCSEC1_IP --sport 23 -j ACCEPT

# pcsec2 -> pcsec1 (Hinrichtung + Rückrichtung)
$IPT -A INPUT  -p tcp -s $PCSEC2_IP -d $PCSEC1_IP --dport 23 -j ACCEPT
$IPT -A OUTPUT -p tcp -s $PCSEC1_IP -d $PCSEC2_IP --sport 23 -j ACCEPT
```

**Dynamisch (10c):**
```bash
# pcsec1 -> pcsec2 (nur Verbindungsaufbau, Antwort über ESTABLISHED)
$IPT -A OUTPUT -p tcp -s $PCSEC1_IP -d $PCSEC2_IP --dport 23 -m conntrack --ctstate NEW -j ACCEPT

# pcsec2 -> pcsec1 (nur Verbindungsaufbau, Antwort über ESTABLISHED)
$IPT -A INPUT  -p tcp -s $PCSEC2_IP -d $PCSEC1_IP --dport 23 -m conntrack --ctstate NEW -j ACCEPT
```

Statt 4 Regeln nur noch 2: Nur der Verbindungsaufbau wird explizit erlaubt, die Antwortpakete laufen automatisch über `ESTABLISHED`.

### 4. Logging bleibt gleich

Das Logging ändert sich funktional nicht. Statt `--syn` (nur SYN-Pakete matchen) wird jetzt `--ctstate NEW` verwendet. Beides matcht den Verbindungsaufbau:

- `--syn` = Matcht TCP-Pakete mit gesetztem SYN-Flag und nicht gesetztem ACK-Flag
- `--ctstate NEW` = Matcht das erste Paket einer neuen Verbindung (egal ob TCP oder UDP)

Für TCP ist das Ergebnis identisch, weil das erste Paket einer TCP-Verbindung immer ein SYN-Paket ist.
