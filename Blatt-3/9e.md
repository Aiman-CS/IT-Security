# Blatt 3, Aufgabe 9e: Firewall testen und Reset-Script anlegen

## Aufgabenstellung

In Aufgabe 9e soll die Firewall aus Aufgabe 9d überprüft werden. Dazu sollen die benötigten Dienste getestet und ein Portscanner verwendet werden.

Zusätzlich soll ein Script angelegt werden, mit dem alle Firewall-Regeln entfernt und die Default-Policies wieder auf `ACCEPT` gesetzt werden können. Dieses Script ist nur für Tests in der Praktikumsumgebung gedacht.

## Ziel der Aufgabe

Ziel war:

- Die statische IPv4-Firewall aus Aufgabe 9d auf `pcsec1` aktivieren
- Die Regeln mit `iptables` prüfen
- Von `pcsec2` aus mit `nmap` gegen `pcsec1` scannen
- SSH praktisch testen
- Logging für SSH, SMTP und DNS prüfen
- FTP und NTP ohne Logging prüfen
- Ein Reset-Script anlegen, das die Firewall-Regeln entfernt und Default-Policies wieder auf `ACCEPT` setzt

## 2. Regeln anzeigen

Danach wurden die gesetzten Regeln angezeigt:

Bedeutung der Optionen:


Die Ausgabe zeigte, dass die Default-Policies auf `DROP` stehen:

```text

```

Das bedeutet: Alles, was nicht explizit erlaubt wurde, wird verworfen.

## 3. Wichtige Regeln der Firewall

Die Firewall erlaubt die geforderten Dienste:

| Dienst | Protokoll | Port | Ergebnis |
|---|---:|---:|---|
| FTP Data | TCP | 20 | erlaubt, ohne Logging |
| FTP Control | TCP | 21 | erlaubt, ohne Logging |
| SSH | TCP | 22 | erlaubt, mit Logging |
| Telnet | TCP | 23 | nur zwischen pcsec1 und pcsec2 erlaubt |
| SMTP | TCP | 25 | erlaubt, mit Logging |
| DNS-Abfragen | UDP | 53 | erlaubt, mit Logging |
| NTP-Abfragen | UDP | 123 | erlaubt, ohne Logging |

Für TCP-Dienste mit Logging wird nur der Verbindungsaufbau geloggt. Das wurde mit `--syn` umgesetzt.

Beispiel:

```bash
iptables -A INPUT -p tcp --dport 22 --syn -j LOG --log-prefix "SSH-IN-NEW: "
```

Das loggt nur TCP-SYN-Pakete, also den Start einer TCP-Verbindung.

## 5. Erklärung der TCP-Portscan-Ergebnisse

### SSH Port 22

```text
22/tcp open ssh
```

SSH ist offen, weil auf `pcsec1` ein SSH-Dienst läuft und die Firewall TCP Port 22 erlaubt.

### FTP Port 20 und 21

```text
20/tcp closed ftp-data
21/tcp closed ftp
```

`closed` bedeutet nicht, dass die Firewall blockiert. Es bedeutet, dass das Paket durchkommt, aber kein Dienst auf diesem Port lauscht.

Das ist bei FTP normal, wenn auf `pcsec1` kein FTP-Server läuft.

### Telnet Port 23

```text
23/tcp closed telnet
```

Auch hier bedeutet `closed`, dass die Firewall den Zugriff nicht filtert, aber kein Telnet-Dienst läuft.

Da der Scan von `pcsec2` kam und Telnet zwischen `pcsec1` und `pcsec2` erlaubt ist, passt dieses Ergebnis.

### SMTP Port 25

```text
25/tcp closed smtp
```

SMTP ist erlaubt, aber es läuft offenbar kein SMTP-Server auf `pcsec1`. Deshalb ist der Port `closed`.

### TCP 53 und TCP 123

```text
53/tcp filtered domain
123/tcp filtered ntp
```

DNS und NTP werden in der Aufgabe als UDP-Dienste behandelt. Deshalb sind TCP 53 und TCP 123 nicht erlaubt und erscheinen als `filtered`.

### HTTP Port 80

```text
80/tcp filtered http
```

HTTP ist nicht erlaubt. Deshalb wird Port 80 von der Firewall gefiltert. Das ist korrekt.

## 7. Erklärung der UDP-Ergebnisse

Bei UDP ist `open|filtered` normal.

Grund:

- UDP ist verbindungslos
- Viele UDP-Dienste senden nicht immer eine Antwort
- Nmap kann daher nicht immer sicher unterscheiden, ob der Port offen ist oder gefiltert wird

Für diese Aufgabe ist wichtig, dass die UDP-Regeln für DNS und NTP vorhanden sind und die Tests Pakete erzeugt haben.

## 14. Reset-Script

Zusätzlich wurde ein Reset-Script angelegt.

Pfad:

```bash
/home/secpgast/Abgaben/9/9e-reset-firewall
```

Zweck:

- alle IPv4-Firewall-Regeln löschen
- Default-Policies auf `ACCEPT` setzen
- Firewall für Tests öffnen

Wichtig: Dieses Script muss nicht ausgeführt werden, wenn die 9d-Firewall aktiv bleiben soll. Es reicht, dass es vorhanden ist. Wenn man es ausführt, öffnet man die Firewall wieder und müsste danach die 9d-Firewall erneut laden.

## 15. Inhalt des Reset-Scripts

```bash
#!/bin/bash

IPT="/sbin/iptables"

# Erst Default-Policies auf ACCEPT setzen
$IPT -P INPUT ACCEPT
$IPT -P OUTPUT ACCEPT
$IPT -P FORWARD ACCEPT

# Filter-Regeln löschen
$IPT -F
$IPT -X

# NAT-Tabelle leeren
$IPT -t nat -F
$IPT -t nat -X

# Mangle-Tabelle leeren
$IPT -t mangle -F
$IPT -t mangle -X

echo "Alle IPv4-Firewall-Regeln wurden entfernt und Default-Policies auf ACCEPT gesetzt."
exit 0
```

Ausführbar machen:

```bash
chmod +x /home/secpgast/Abgaben/9/9e-reset-firewall
```

Syntax prüfen:

```bash
bash -n /home/secpgast/Abgaben/9/9e-reset-firewall
echo $?
```

Ein Rückgabewert von `0` bedeutet, dass die Syntax korrekt ist.
