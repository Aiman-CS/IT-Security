# Aufgabe 5a) – TCP-Verbindungsauf- und -abbau mitschneiden

## Ziel
TCP-Verbindungsaufbau, Datenübertragung und Verbindungsabbau zu einem über IP erreichbaren Rechner aufzeichnen und die Pakete den drei Phasen zuordnen.

## Durchführung

### 1. SSH auf pcsec1
```bash
ssh pcsec1
```

### 2. tcpdump starten (im Hintergrund)
```bash
tcpdump -i ens7 -n -S tcp and host 10.153.210.254 -c 20 -w /tmp/tcp_capture.pcap &
```
- `-i ens7` → Interface auswählen
- `-n` → keine DNS-Auflösung
- `-S` → absolute Sequenznummern anzeigen
- `tcp and host 10.153.210.254` → nur TCP-Pakete zum/vom secserver filtern
- `-c 20` → maximal 20 Pakete aufzeichnen
- `-w /tmp/tcp_capture.pcap` → in Datei speichern

### 3. TCP-Verbindung erzeugen (FTP auf secserver)
```bash
echo "QUIT" | nc -w 3 10.153.210.254 21
```
Verbindet sich zum FTP-Server (Port 21), sendet QUIT und beendet die Verbindung sauber.

### 4. Capture lesen
```bash
tcpdump -n -S -r /tmp/tcp_capture.pcap
```

## Zuordnung der Pakete

### Verbindungsaufbau (3-Way Handshake) – Pakete 1–3

| Paket | Richtung | Flags | Bedeutung |
|-------|----------|-------|-----------|
| 1 | pcsec1 → secserver | [S] SYN | Client initiiert Verbindung |
| 2 | secserver → pcsec1 | [S.] SYN+ACK | Server akzeptiert und bestätigt |
| 3 | pcsec1 → secserver | [.] ACK | Client bestätigt – Verbindung steht |

### Datenübertragung – Pakete 4–8

| Paket | Richtung | Flags | Bedeutung |
|-------|----------|-------|-----------|
| 4 | secserver → pcsec1 | [P.] PSH+ACK | Server sendet FTP-Banner "220 (vsFTPd 3.0.3)" |
| 5 | pcsec1 → secserver | [.] ACK | Client bestätigt Empfang |
| 6 | pcsec1 → secserver | [P.] PSH+ACK | Client sendet "QUIT\r\n" (6 Bytes) |
| 7 | secserver → pcsec1 | [.] ACK | Server bestätigt Empfang |
| 8 | secserver → pcsec1 | [P.] PSH+ACK | Server sendet "221 Goodbye." |

### Verbindungsabbau (FIN-Sequenz) – Pakete 9–11

| Paket | Richtung | Flags | Bedeutung |
|-------|----------|-------|-----------|
| 9 | secserver → pcsec1 | [F.] FIN+ACK | Server initiiert Verbindungsabbau |
| 10 | pcsec1 → secserver | [F.] FIN+ACK | Client bestätigt Server-FIN und sendet eigenes FIN |
| 11 | secserver → pcsec1 | [.] ACK | Server bestätigt Client-FIN – Verbindung geschlossen |

---

## Erklärung der Flags

- `[S]` = SYN – Synchronisation, Verbindungsaufbau
- `[S.]` = SYN+ACK – Bestätigung des SYN
- `[.]` = ACK – Bestätigung
- `[P.]` = PSH+ACK – Daten werden sofort an die Anwendung weitergegeben
- `[F.]` = FIN+ACK – Verbindungsabbau eingeleitet

## Hinweis
Der Verbindungsabbau ist hier leicht optimiert: Statt der klassischen 4 Pakete (FIN, ACK, FIN, ACK) kombiniert Paket 10 das ACK für den Server-FIN mit dem eigenen FIN in einem einzigen Paket.
