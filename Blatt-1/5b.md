# Praktikum IT-Sicherheit, Blatt 01 Guide

Dieser Guide fasst die wichtigsten Befehle, Tests und Erklärungen für die bisher bearbeiteten Aufgaben zusammen.

## Grundregeln

- `ens2` nicht verändern.
- `gwsec` ist der Router zwischen internem Gruppennetz und Praktikumsnetz.
- `ens7` zeigt zum internen Gruppennetz.
- `ens8` zeigt zum externen Praktikumsnetz.
- Nach jeder Änderung mit `ip addr`, `ip route`, `ip -6 addr` oder `ip -6 route` prüfen.

## 1. IP-Adressen und Netzmasken

### 1a, nutzbare IPv4-Adressen und Broadcast

#### Netz `10.153.210.0/29`

Ein `/29` Netz hat:

```text
32 - 29 = 3 Hostbits
2^3 = 8 Adressen
```

Bereich:

```text
10.153.210.0   Netzadresse
10.153.210.1   nutzbar
10.153.210.2   nutzbar
10.153.210.3   nutzbar
10.153.210.4   nutzbar
10.153.210.5   nutzbar
10.153.210.6   nutzbar
10.153.210.7   Broadcast
```

Antwort:

```text
Nutzbare Adressen: 10.153.210.1 bis 10.153.210.6
Broadcast: 10.153.210.7
```

#### Netz `10.153.210.192/26`

Ein `/26` Netz hat:

```text
32 - 26 = 6 Hostbits
2^6 = 64 Adressen
```

Bereich:

```text
10.153.210.192   Netzadresse
10.153.210.193 bis 10.153.210.254   nutzbar
10.153.210.255   Broadcast
```

Antwort:

```text
Nutzbare Adressen: 10.153.210.193 bis 10.153.210.254
Broadcast: 10.153.210.255
```

### 1b, kleinstes gemeinsames IPv4-Netz

Gesucht ist das kleinste Netz, das alle internen IPv4-Adressen abdeckt.

Bereich:

```text
10.153.210.0 bis 10.153.210.255
```

Ergebnis:

```text
10.153.210.0/24
```

Begründung:

```text
/24 bedeutet 8 Hostbits.
2^8 = 256 Adressen.
Das deckt .0 bis .255 ab.
```

### 1c, kleinstes gemeinsames IPv6-Präfix

Gegebene IPv6-Netze:

```text
2001:4ca0:4001:f00::/64
2001:4ca0:4001:f21::/64
```

Vergleich des vierten Blocks als 16 Bit:

```text
0f00 = 0000 1111 0000 0000
0f21 = 0000 1111 0010 0001
```

Gemeinsam:

```text
erste 10 Bits im vierten Block
erste 3 Blöcke = 48 Bit
48 + 10 = 58
```

Ergebnis:

```text
2001:4ca0:4001:f00::/58
```

## 2. Netzwerkkarten und Tabellen

### 2a, alte Tools und moderne `ip` Befehle

```text
arp        -> ip neigh
netstat -r -> ip route
ifconfig   -> ip addr
```

Bedeutung:

```text
ip neigh zeigt ARP beziehungsweise Neighbor Cache.
ip route zeigt die Routing-Tabelle.
ip addr zeigt Interfaces und Adressen.
```

### 2b, Interfaces konfigurieren

#### gwsec

```bash
ip addr add 10.153.210.1/29 dev ens7
ip addr add 2001:4ca0:4001:f21::1/64 dev ens7
ip addr add 10.153.210.193/26 dev ens8
ip addr add 2001:4ca0:4001:f00::21/64 dev ens8

ip link set ens7 up
ip link set ens8 up
```

Prüfen:

```bash
ip addr
ip -6 addr
```

#### pcsec1

```bash
ip addr add 10.153.210.2/29 dev ens7
ip addr add 2001:4ca0:4001:f21::2/64 dev ens7
ip link set ens7 up
```

#### pcsec2

```bash
ip addr add 10.153.210.3/29 dev ens7
ip addr add 2001:4ca0:4001:f21::3/64 dev ens7
ip link set ens7 up
```

### 2c, Erreichbarkeit testen

Auf `pcsec1`:

```bash
ping -c 3 10.153.210.1
ping -c 3 10.153.210.3
ping -c 3 10.153.210.254
```

Interpretation:

```text
10.153.210.1 ist gwsec im gleichen Subnetz.
10.153.210.3 ist pcsec2 im gleichen Subnetz.
10.153.210.254 liegt außerhalb und braucht Routing.
```

### 2d, ARP und Routing-Tabelle prüfen

```bash
ip neigh
ip route
```

Antwort:

```text
Die ARP-Tabelle wird durch Kommunikation gefüllt und enthält IP zu MAC Zuordnungen.
Die Routing-Tabelle enthält direkt angeschlossene Netze und später statische Routen.
```

## 3. Statische IPv4-Routen

### 3a, Netzrouten auf pcsec1 und pcsec2

Auf `pcsec1` und `pcsec2`:

```bash
ip route replace 10.153.210.0/24 via 10.153.210.1 dev ens7
```

Optional, falls eine alte spezifische Route stört:

```bash
ip route del 10.153.210.192/26
```

Prüfen:

```bash
ip route
```

Erwartet:

```text
10.153.210.0/24 via 10.153.210.1 dev ens7
```

Bedeutung:

```text
Alle Ziele im Bereich 10.153.210.0 bis 10.153.210.255 gehen über gwsec.
```

### 3b, IPv4-Forwarding und Default-Route auf gwsec

Auf `gwsec`:

```bash
sysctl -w net.ipv4.ip_forward=1
ip route add default via 10.153.210.254
```

Falls die Route schon existiert:

```bash
ip route replace default via 10.153.210.254
```

Prüfen:

```bash
sysctl net.ipv4.ip_forward
ip route
```

Erwartet:

```text
net.ipv4.ip_forward = 1
default via 10.153.210.254
```

### 3c, Default-Route auf pcsec1 und pcsec2

Auf `pcsec1` und `pcsec2`:

```bash
ip route add default via 10.153.210.1 dev ens7
```

Falls sie schon existiert:

```bash
ip route replace default via 10.153.210.1 dev ens7
```

Bedeutung:

```text
Alle unbekannten IPv4-Ziele gehen über gwsec.
```

### 3d, Tabellen prüfen

```bash
ip neigh
ip route
```

Antwort:

```text
Die Routing-Tabelle enthält nun Netzrouten und eine Default-Route.
Die ARP-Tabelle enthält Einträge für den Router als nächsten Hop.
```

## 4. ARP und IPv6 Neighbor Discovery

### 4a, ARP beobachten

Auf `pcsec1`, Terminal 1:

```bash
ip neigh flush all
tcpdump -i ens7 -n -e arp
```

Auf `pcsec1`, Terminal 2:

```bash
ping -c 3 10.153.210.1
ping -c 3 10.153.210.254
```

Beobachtung:

```text
Für Ziele im gleichen Subnetz wird direkt die Ziel-IP per ARP gesucht.
Für Ziele außerhalb des Subnetzes wird die MAC-Adresse des Routers gesucht.
```

### 4b, ARP und Routing danach prüfen

```bash
ip neigh
ip route
```

Antwort:

```text
ARP hat neue IP zu MAC Einträge gelernt.
Die Routing-Tabelle ändert sich durch Ping nicht.
```

### 4c, IPv6 Neighbor Discovery beobachten

Auf `pcsec1`, Terminal 1:

```bash
ip -6 neigh flush all
tcpdump -i ens7 -n -vv 'icmp6'
```

Auf `pcsec1`, Terminal 2:

```bash
ping6 -c 3 2001:4ca0:4001:f21::1
```

Beobachtung:

```text
Neighbor Solicitation fragt nach der MAC-Adresse.
Neighbor Advertisement antwortet mit der MAC-Adresse.
Danach folgen Echo Request und Echo Reply.
```

Kurzantwort:

```text
IPv6 verwendet Neighbor Discovery statt ARP.
Die Nachrichten laufen über ICMPv6 und Multicast, nicht über ARP Broadcast.
```

### 4d, IPv6 Default-Route auf pcsec1 und pcsec2

Auf `pcsec1` und `pcsec2`:

```bash
ip -6 route add default via 2001:4ca0:4001:f21::1 dev ens7
```

Falls vorhanden:

```bash
ip -6 route replace default via 2001:4ca0:4001:f21::1 dev ens7
```

Auf `gwsec` IPv6 Forwarding prüfen:

```bash
sysctl net.ipv6.conf.all.forwarding
```

Falls `0`:

```bash
sysctl -w net.ipv6.conf.all.forwarding=1
```

### 4e, Fehler in IPv6-Routingtabelle korrigieren

Auf `gwsec` prüfen:

```bash
ip -6 route
```

Die direkte Route zum externen Segment muss vorhanden sein:

```bash
ip -6 route add 2001:4ca0:4001:f00::/64 dev ens8
```

Die fehlerhafte oder zu breite Route entfernen:

```bash
ip -6 route del 2001:4ca0:4001:f00::/56
```

Korrekte Route zum Zielnetz setzen:

```bash
ip -6 route replace 2001:4ca0:4001:f7f::/64 via 2001:4ca0:4001:f00::ff dev ens8
```

Prüfen:

```bash
ip -6 route
```

Erwartet:

```text
2001:4ca0:4001:f00::/64 dev ens8
2001:4ca0:4001:f7f::/64 via 2001:4ca0:4001:f00::ff dev ens8
```

Bedeutung:

```text
gwsec erreicht den nächsten Router findmegw über f00::/64.
Für das Zielnetz f7f::/64 wird der Next-Hop f00::ff genutzt.
```

### 4f, Auswirkung des Fehlers und Lösung

Antwort:

```text
Der Fehler in der Routingtabelle führte dazu, dass Pakete zum Zielnetz nicht korrekt weitergeleitet wurden. Die Lösung bestand darin, die falsche Route zu entfernen und eine korrekte Route zum Zielnetz 2001:4ca0:4001:f7f::/64 über den Next-Hop 2001:4ca0:4001:f00::ff einzutragen.
```

### 4g, findme-Adresse finden

Der Bereich:

```text
2001:4ca0:4001:f7f::1:0/124
```

hat:

```text
128 - 124 = 4 Hostbits
2^4 = 16 Adressen
```

Mögliche Adressen:

```text
2001:4ca0:4001:f7f::1:0
...
2001:4ca0:4001:f7f::1:f
```

Da `findme` nicht auf Ping antwortet, mitschneiden:

```bash
tcpdump -i ens8 -n -vv icmp6 | grep f7f
```

Gesucht sind Zeilen wie:

```text
neighbor solicitation, who has 2001:4ca0:4001:f7f::1:x
neighbor advertisement, tgt is 2001:4ca0:4001:f7f::1:x
```

## 5. Mitschneiden des Netzverkehrs

### 5a, TCP-Verbindungsaufbau und Abbau beobachten

Auf `pcsec1`, Terminal 1:

```bash
tcpdump -i ens7 -n -vv host 10.153.210.254 and tcp
```

Auf `pcsec1`, Terminal 2:

```bash
nc 10.153.210.254 21
```

Falls `nc` nicht vorhanden ist:

```bash
telnet 10.153.210.254 21
```

Zuordnen:

```text
SYN, SYN/ACK, ACK        Verbindungsaufbau
Pakete mit Nutzdaten     Datenübertragung
FIN/ACK oder RST         Verbindungsabbau
```

### 5b, Layer-2-Infrastruktur vergleichen

Auf `gwsec`, internes Interface:

```bash
tcpdump -i ens7 -n -e -c 5
```

Parallel auf `pcsec1`:

```bash
ping -c 3 10.153.210.1
```

Auf `gwsec`, externes Interface:

```bash
tcpdump -i ens8 -n -e -c 5
```

Parallel auf `pcsec1`:

```bash
ping -c 3 10.153.210.254
```

Wichtig:

```text
-e zeigt Ethernet Header und damit MAC-Adressen.
```

Beispiel ens7:

```text
52:54:00:e3:07:5d > 52:54:00:36:4d:0e
10.153.210.2 > 10.153.210.1 ICMP echo request
```

Antwort:

```text
Auf ens7 ist Verkehr des internen Gruppennetzes sichtbar, z.B. zwischen pcsec1 und gwsec. Die MAC-Adressen gehören zu den internen Geräten.

Auf ens8 ist Verkehr des externen Praktikumsnetzes sichtbar, z.B. zwischen gwsec und secserver oder anderen Infrastrukturrechnern. Dort treten andere MAC-Adressen auf.

Daraus folgt, dass ens7 und ens8 unterschiedliche Layer-2-Segmente sind. gwsec verbindet beide Segmente als Router auf Layer 3.
```

### 5c, FTP Passwort mitschneiden und Script erstellen

FTP ist unverschlüsselt, daher sind Benutzername und Passwort im Klartext sichtbar.

Auf `gwsec`:

```bash
tcpdump -i ens8 -A port 21
```

Oder gefiltert:

```bash
tcpdump -i ens8 -A | grep -E "USER|PASS"
```

Script-Pfad:

```text
/home/secpgast/Abgaben/5/ftp
```

Beispielscript:

```bash
#!/bin/bash

TMPFILE="/tmp/ftp_time_$$"
date +%s > "$TMPFILE"

ftp -n 10.153.210.254 <<EOF
user <USERNAME> <PASSWORT>
put "$TMPFILE" gruppeXX.secp.lab.nm.ifi.lmu.de
bye
EOF

rm -f "$TMPFILE"
```

Ausführbar machen:

```bash
chmod +x /home/secpgast/Abgaben/5/ftp
```

Test:

```bash
/home/secpgast/Abgaben/5/ftp
```

Wichtig:

```text
Die Datei auf dem FTP-Server darf nur die Unixzeit enthalten.
Der Dateiname muss der Hostname sein, z.B. gruppe09.secp.lab.nm.ifi.lmu.de.
Das Script muss ausführbar sein.
```
