# Aufgabe 6c: Scan von gwsec auf 10.153.210.192/26

## Befehl

```bash
nmap 10.153.210.192/26
```

---

## Zusammenfassung

In Aufgabe **6c** soll der normale nmap-Scan aus Aufgabe **6b i** wiederholt werden.

Der Unterschied ist:

- In Aufgabe 6b wurde von einem **pcsec-System** gescannt.
- In Aufgabe 6c wird derselbe Scan von **gwsec** ausgeführt.
- Es wird wieder **ohne Optionen** gescannt.
- Zielnetz bleibt `10.153.210.192/26`.

Der Zweck ist, die Ergebnisse zu vergleichen und zu erklären, welche zusätzlichen Informationen beim Scan von `gwsec` sichtbar werden.

---

## Ergebnis des Scans von gwsec

Ausgeführt wurde:

```bash
nmap 10.153.210.192/26
```

Gefunden wurden wieder 3 erreichbare Hosts:

```text
test4all.secp.lab.nm.ifi.lmu.de (10.153.210.251)
defaultgw.secp.lab.nm.ifi.lmu.de (10.153.210.254)
10.153.210.193
```

Die offenen Ports waren:

```text
10.153.210.251     22/tcp open ssh
10.153.210.254     21/tcp open ftp
10.153.210.193     22/tcp open ssh
```

Zusätzlich wurden bei zwei Hosts MAC-Adressen angezeigt:

```text
10.153.210.251     MAC Address: 52:54:00:3A:56:32 (QEMU virtual NIC)
10.153.210.254     MAC Address: FE:54:00:3A:56:32 (Unknown)
```

Bei `10.153.210.193` wurde keine MAC-Adresse angezeigt. Die Latenz ist dort aber extrem niedrig:

```text
Host is up (0.0000070s latency)
```

Das deutet darauf hin, dass `10.153.210.193` sehr wahrscheinlich die eigene Adresse von `gwsec` in diesem Netz ist.

---

## Kurze Antwort für die Abgabe

```text
Der Scan von gwsec auf 10.153.210.192/26 liefert dieselben erreichbaren Hosts und offenen Dienste wie der Scan von pcsec: zwei SSH-Dienste auf Port 22 und einen FTP-Dienst auf Port 21. Zusätzlich zeigt nmap beim Scan von gwsec MAC-Adressen für die Hosts 10.153.210.251 und 10.153.210.254 an. Das liegt daran, dass gwsec sich im selben Layer-2-Netz wie die Zielsysteme befindet und nmap dadurch ARP verwenden kann. Von pcsec aus wurde das Zielnetz über einen Router erreicht, deshalb waren dort die MAC-Adressen der Zielhosts nicht sichtbar. MAC-Adressen werden nicht über Router hinweg weitergeleitet.
```

---

# Detaillierte Erklärung

## 1. Was wurde gemacht?

Von `gwsec` aus wurde folgender Scan ausgeführt:

```bash
nmap 10.153.210.192/26
```

Das ist ein normaler nmap-Scan ohne zusätzliche Optionen.

Nmap macht dabei:

1. Es prüft, welche Hosts im Netz `10.153.210.192/26` erreichbar sind.
2. Für die erreichbaren Hosts scannt es die 1000 häufigsten TCP-Ports.
3. Es zeigt offene Ports und die dazugehörigen Dienste an.

Das Netz `10.153.210.192/26` umfasst 64 IP-Adressen:

```text
10.153.210.192 bis 10.153.210.255
```

---

## 2. Welche Hosts wurden gefunden?

Der Scan hat 3 Hosts gefunden:

```text
10.153.210.251
10.153.210.254
10.153.210.193
```

In der nmap-Ausgabe stehen dazu:

```text
Nmap scan report for test4all.secp.lab.nm.ifi.lmu.de (10.153.210.251)
Nmap scan report for defaultgw.secp.lab.nm.ifi.lmu.de (10.153.210.254)
Nmap scan report for 10.153.210.193
```

Das bedeutet:

- `10.153.210.251` ist erreichbar.
- `10.153.210.254` ist erreichbar.
- `10.153.210.193` ist erreichbar.

---

## 3. Welche Ports wurden gefunden?

### Host `10.153.210.251`

```text
PORT   STATE SERVICE
22/tcp open  ssh
```

Interpretation:

- Port 22 ist offen.
- Auf Port 22 läuft SSH.
- SSH wird für Remote-Login und Verwaltung verwendet.

Zusätzlich wurde eine MAC-Adresse angezeigt:

```text
MAC Address: 52:54:00:3A:56:32 (QEMU virtual NIC)
```

Das bedeutet, dass nmap die Netzwerkkarte des Hosts im lokalen Netz erkennen konnte. `QEMU virtual NIC` zeigt, dass es sich um eine virtuelle Netzwerkkarte handelt.

---

### Host `10.153.210.254`

```text
PORT   STATE SERVICE
21/tcp open  ftp
```

Interpretation:

- Port 21 ist offen.
- Auf Port 21 läuft FTP.
- FTP wird für Dateiübertragung verwendet.

Zusätzlich wurde eine MAC-Adresse angezeigt:

```text
MAC Address: FE:54:00:3A:56:32 (Unknown)
```

Das bedeutet, dass nmap auch hier eine MAC-Adresse sehen konnte. Der Hersteller wurde aber nicht eindeutig erkannt, deshalb steht dort `Unknown`.

---

### Host `10.153.210.193`

```text
PORT   STATE SERVICE
22/tcp open  ssh
```

Interpretation:

- Port 22 ist offen.
- Auf Port 22 läuft SSH.

Hier wurde keine MAC-Adresse angezeigt. Gleichzeitig war die Latenz extrem niedrig:

```text
Host is up (0.0000070s latency)
```

Das ist ein Hinweis darauf, dass `10.153.210.193` wahrscheinlich die eigene Adresse von `gwsec` in diesem Netz ist. Wenn ein System sich selbst scannt, läuft die Antwort lokal über den eigenen Netzwerkstack, deshalb ist die Latenz sehr klein und nmap zeigt keine externe MAC-Adresse an.

---

## 4. Vergleich mit dem Scan von pcsec

Beim Scan von `pcsec` auf dasselbe Netz wurden ebenfalls 3 Hosts gefunden:

```text
10.153.210.193       22/tcp open ssh
10.153.210.251       22/tcp open ssh
10.153.210.254       21/tcp open ftp
```

Der wichtigste Unterschied:

Beim Scan von `gwsec` wurden zusätzlich MAC-Adressen angezeigt:

```text
10.153.210.251       MAC Address: 52:54:00:3A:56:32
10.153.210.254       MAC Address: FE:54:00:3A:56:32
```

Beim Scan von `pcsec` wurden für dieses Netz keine MAC-Adressen angezeigt.

---

## 5. Warum sieht gwsec zusätzliche Informationen?

`gwsec` befindet sich sehr wahrscheinlich direkt im Netz `10.153.210.192/26`.

Wenn der Scanner und das Ziel im selben lokalen Netz sind, kann nmap ARP verwenden.

ARP bedeutet Address Resolution Protocol. Damit wird zu einer IP-Adresse die passende MAC-Adresse gesucht.

Beispiel:

```text
IP-Adresse:  10.153.210.251
MAC-Adresse: 52:54:00:3A:56:32
```

Diese Information ist nur im lokalen Layer-2-Netz sichtbar.

---

## 6. Warum sah pcsec diese MAC-Adressen nicht?

Bei `pcsec` zeigte die Routing-Tabelle:

```text
10.153.210.192/26 via 10.153.210.1 dev ens7
```

Das bedeutet:

- `pcsec` erreicht das Netz `10.153.210.192/26` über den Router `10.153.210.1`.
- Der Verkehr wird also geroutet.
- Bei geroutetem Verkehr sieht `pcsec` nicht die MAC-Adressen der eigentlichen Zielhosts.
- `pcsec` sieht auf Layer 2 nur den nächsten Hop, also den Router.

MAC-Adressen werden nicht über Router hinweg weitergeleitet. Deshalb konnte nmap von `pcsec` aus keine MAC-Adressen der Zielsysteme im Netz `10.153.210.192/26` anzeigen.

---

## 7. Was bedeutet die niedrigere Latenz?

Beim Scan von `gwsec` sind die Latenzen sehr klein:

```text
10.153.210.251       0.0012s
10.153.210.254       0.00049s
10.153.210.193       0.0000070s
```

Das zeigt:

- Die Systeme sind sehr nah im Netzwerk.
- `10.153.210.193` ist wahrscheinlich lokal auf `gwsec`, weil die Latenz fast null ist.
- Die anderen Hosts liegen vermutlich im selben virtuellen Netz.

# Endgültige Antwort für Aufgabe 6c

```text
Beim Scan von gwsec auf 10.153.210.192/26 wurden wie beim Scan von pcsec drei erreichbare Hosts gefunden: 10.153.210.193 mit SSH auf Port 22, 10.153.210.251 mit SSH auf Port 22 und 10.153.210.254 mit FTP auf Port 21.

Zusätzlich zeigt nmap beim Scan von gwsec MAC-Adressen für 10.153.210.251 und 10.153.210.254 an. Diese Information war beim Scan von pcsec nicht sichtbar. Der Grund ist, dass gwsec direkt im Zielnetz beziehungsweise im gleichen Layer-2-Segment liegt und nmap deshalb ARP verwenden kann. ARP liefert die MAC-Adresse zu einer IP-Adresse. Von pcsec aus wurde das Netz dagegen über einen Router erreicht, deshalb waren die MAC-Adressen der Zielhosts nicht sichtbar. MAC-Adressen werden nur im lokalen Netz verwendet und nicht über Router hinweg weitergegeben.

Außerdem hat 10.153.210.193 eine extrem niedrige Latenz und keine angezeigte MAC-Adresse. Das spricht dafür, dass diese Adresse zu gwsec selbst gehört und der Host lokal gescannt wurde.
```
