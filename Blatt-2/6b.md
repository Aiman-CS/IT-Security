# Aufgabe 6b: Netzwerkscans mit nmap

## Zusammenfassung

In Aufgabe **6b** sollen mit `nmap` zwei Netzbereiche untersucht werden:

1. das vorgegebene Netz `10.153.210.192/26`
2. das eigene Subnetz `10.153.210.0/29`

Das eigene Subnetz wurde über die IP-Konfiguration bestimmt. Auf `pcsec1` wurde folgende IPv4-Adresse angezeigt:

```text
inet 10.153.210.2/29 scope global ens7
```

Außerdem zeigt die Routing-Tabelle:

```text
10.153.210.0/29 dev ens7 proto kernel scope link src 10.153.210.2
```

Damit ist das eigene Subnetz:

```text
10.153.210.0/29
```

Ziel der Aufgabe ist es, mit verschiedenen Scan-Varianten herauszufinden:

- welche Hosts erreichbar sind
- welche Ports offen sind
- welche Dienste auf diesen Ports laufen
- ob nmap das Betriebssystem erkennen kann
- wie sich ein normaler Scan von einem FIN-Scan unterscheidet

---

## Befehle

```bash
nmap 10.153.210.192/26
nmap 10.153.210.0/29

nmap -O 10.153.210.192/26
nmap -O 10.153.210.0/29

nmap -p 20-1000 10.153.210.192/26
nmap -p 20-1000 10.153.210.0/29

nmap -sF 10.153.210.192/26
nmap -sF 10.153.210.0/29
```

---

# Detaillierte Erklärung

## i. Scan ohne Optionen

### Befehl für das vorgegebene Netz

```bash
nmap 10.153.210.192/26
```

### Bedeutung

Dieser Befehl führt einen normalen Standardscan mit `nmap` aus.

Dabei macht nmap im Wesentlichen zwei Dinge:

1. Es prüft, welche Hosts im angegebenen Netz erreichbar sind.
2. Für erreichbare Hosts scannt es die Standard-TCP-Ports.

Wenn keine zusätzlichen Optionen angegeben werden, scannt nmap standardmäßig die 1000 häufigsten TCP-Ports.

### Ergebnis für `10.153.210.192/26`

Gefunden wurden 3 erreichbare Hosts:

```text
10.153.210.193
test4all.secp.lab.nm.ifi.lmu.de (10.153.210.251)
defaultgw.secp.lab.nm.ifi.lmu.de (10.153.210.254)
```

Die offenen Ports waren:

```text
10.153.210.193                         22/tcp open ssh
10.153.210.251 test4all                 22/tcp open ssh
10.153.210.254 defaultgw                21/tcp open ftp
```

Das bedeutet:

- Auf `10.153.210.193` ist SSH erreichbar.
- Auf `10.153.210.251` ist SSH erreichbar.
- Auf `10.153.210.254` ist FTP erreichbar.

Bei den ersten beiden Hosts ist also Port 22 offen. Port 22 gehört typischerweise zu SSH. Beim Gateway ist Port 21 offen. Port 21 gehört typischerweise zu FTP.

Die Ausgabe:

```text
Not shown: 999 closed ports
```

bedeutet, dass nmap 1000 Standardports geprüft hat. Davon waren 999 geschlossen und nur ein Port war offen.

### Befehl für das eigene Subnetz

```bash
nmap 10.153.210.0/29
```

### Ergebnis für `10.153.210.0/29`

Gefunden wurden 3 erreichbare Hosts:

```text
pcsec01.secp.lab.nm.ifi.lmu.de (10.153.210.1)
pcsec02.secp.lab.nm.ifi.lmu.de (10.153.210.2)
pcsec03.secp.lab.nm.ifi.lmu.de (10.153.210.3)
```

Die offenen Ports waren:

```text
10.153.210.1 pcsec01                  22/tcp open ssh
10.153.210.2 pcsec02                  22/tcp open ssh
10.153.210.3 pcsec03                  22/tcp open ssh
```

Das bedeutet:

- Alle drei erreichbaren Hosts im eigenen Subnetz haben SSH offen.
- Auf allen drei Hosts ist Port 22 offen.
- Die übrigen 999 Standardports wurden als geschlossen angezeigt.

Da auf `pcsec1` gescannt wurde, ist `10.153.210.2` der eigene Host. Deshalb zeigt nmap bei diesem Host eine sehr geringe Latenz:

```text
Host is up (0.0000070s latency)
```

## ii. Fingerprint-Scan / OS Detection

### Befehl für das vorgegebene Netz

```bash
nmap -O 10.153.210.192/26
```

### Bedeutung

Die Option `-O` aktiviert die Betriebssystemerkennung.

Nmap versucht dabei anhand von Netzwerkantworten zu erkennen, welches Betriebssystem auf einem Host läuft. Das nennt man auch OS Detection oder Fingerprinting.

Nmap betrachtet dabei unter anderem:

- wie das Zielsystem auf bestimmte TCP-Pakete antwortet
- welche Ports offen oder geschlossen sind
- wie sich der TCP/IP-Stack verhält
- TTL-Werte und andere Netzwerkmerkmale

Das Ergebnis ist keine hundertprozentige Garantie, sondern eine Schätzung anhand eines Fingerprints.

### Ergebnis für `10.153.210.192/26`

Für alle drei erreichbaren Hosts wurde Linux erkannt:

```text
10.153.210.193
Device type: general purpose
Running: Linux 3.X|4.X
OS details: Linux 3.2 - 4.6
Network Distance: 1 hop
```

```text
test4all.secp.lab.nm.ifi.lmu.de (10.153.210.251)
Device type: general purpose
Running: Linux 3.X|4.X
OS details: Linux 3.2 - 4.6
Network Distance: 2 hops
```

```text
defaultgw.secp.lab.nm.ifi.lmu.de (10.153.210.254)
Device type: general purpose
Running: Linux 3.X|4.X
OS details: Linux 3.2 - 4.6
Network Distance: 2 hops
```

Interpretation:

- Alle drei Systeme wirken für nmap wie Linux-Systeme.
- Nmap schätzt den Kernelbereich auf Linux 3.x bis 4.x.
- `10.153.210.193` ist 1 Hop entfernt.
- `10.153.210.251` und `10.153.210.254` sind 2 Hops entfernt.

Der normale Portscan-Teil bleibt ähnlich wie bei i:

```text
10.153.210.193       22/tcp open ssh
10.153.210.251       22/tcp open ssh
10.153.210.254       21/tcp open ftp
```

### Befehl für das eigene Subnetz

```bash
nmap -O 10.153.210.0/29
```

### Ergebnis für `10.153.210.0/29`

Auch im eigenen Subnetz wurden wieder 3 erreichbare Hosts gefunden:

```text
pcsec01.secp.lab.nm.ifi.lmu.de (10.153.210.1)
pcsec02.secp.lab.nm.ifi.lmu.de (10.153.210.2)
pcsec03.secp.lab.nm.ifi.lmu.de (10.153.210.3)
```

Für `pcsec01`:

```text
Device type: general purpose
Running: Linux 3.X|4.X
OS details: Linux 3.2 - 4.6
Network Distance: 1 hop
```

Für `pcsec03`:

```text
Device type: general purpose
Running: Linux 3.X|4.X
OS details: Linux 3.2 - 4.6
Network Distance: 1 hop
```

Für `pcsec02`, also den eigenen Host bei Scan von `pcsec1`:

```text
Device type: general purpose
Running: Linux 3.X
OS details: Linux 3.7 - 3.11
Network Distance: 0 hops
```

Interpretation:

- Die Systeme werden als Linux-Systeme erkannt.
- Der eigene Host hat `Network Distance: 0 hops`, weil er lokal auf derselben Maschine gescannt wird.
- Die anderen Hosts im gleichen Subnetz sind 1 Hop entfernt.
- Bei allen gefundenen Hosts ist Port 22 für SSH offen.

## iii. Scan der Ports 20 bis 1000

### Befehl für das vorgegebene Netz

```bash
nmap -p 20-1000 10.153.210.192/26
```

### Bedeutung

Die Option `-p 20-1000` beschränkt den Scan auf die TCP-Ports 20 bis 1000.

Das bedeutet:

- Es werden nicht automatisch die 1000 häufigsten Ports gescannt.
- Stattdessen wird genau der Bereich von Port 20 bis Port 1000 geprüft.

Dieser Bereich enthält viele bekannte Dienste, zum Beispiel:

```text
20/tcp FTP data
21/tcp FTP
22/tcp SSH
25/tcp SMTP
53/tcp DNS
80/tcp HTTP
443/tcp HTTPS
```

### Ergebnis für `10.153.210.192/26`

Gefunden wurden wieder 3 erreichbare Hosts:

```text
10.153.210.193
test4all.secp.lab.nm.ifi.lmu.de (10.153.210.251)
defaultgw.secp.lab.nm.ifi.lmu.de (10.153.210.254)
```

Die offenen Ports waren wieder:

```text
10.153.210.193                         22/tcp open ssh
10.153.210.251 test4all                 22/tcp open ssh
10.153.210.254 defaultgw                21/tcp open ftp
```

Die Ausgabe:

```text
Not shown: 980 closed ports
```

bedeutet:

- Im Bereich 20 bis 1000 liegen 981 Ports.
- Davon war jeweils 1 Port offen.
- Die anderen 980 Ports waren geschlossen.

Damit bestätigt dieser Scan das Ergebnis aus dem Standardsccan: In diesem Netz wurden SSH auf zwei Hosts und FTP auf einem Host gefunden.

### Befehl für das eigene Subnetz

```bash
nmap -p 20-1000 10.153.210.0/29
```

### Ergebnis für `10.153.210.0/29`

Gefunden wurden wieder 3 Hosts:

```text
pcsec01.secp.lab.nm.ifi.lmu.de (10.153.210.1)
pcsec02.secp.lab.nm.ifi.lmu.de (10.153.210.2)
pcsec03.secp.lab.nm.ifi.lmu.de (10.153.210.3)
```

Die offenen Ports waren:

```text
10.153.210.1 pcsec01                  22/tcp open ssh
10.153.210.2 pcsec02                  22/tcp open ssh
10.153.210.3 pcsec03                  22/tcp open ssh
```

Interpretation:

- Im eigenen Subnetz ist auf allen drei erreichbaren Hosts SSH offen.
- Port 22 liegt im Bereich 20 bis 1000, deshalb wird er gefunden.
- Die übrigen 980 Ports im gescannten Bereich sind geschlossen.

## iv. FIN-Scan

### Befehl für das vorgegebene Netz

```bash
nmap -sF 10.153.210.192/26
```

### Bedeutung

Die Option `-sF` startet einen FIN-Scan.

Dabei sendet nmap TCP-Pakete mit gesetztem FIN-Flag. Das FIN-Flag wird normalerweise genutzt, um eine TCP-Verbindung zu beenden.

Der FIN-Scan funktioniert anders als ein normaler TCP-Scan:

- Bei geschlossenen Ports antwortet ein System typischerweise mit einem RST-Paket.
- Bei offenen Ports kommt häufig keine Antwort.
- Wenn keine Antwort kommt, kann nmap oft nicht sicher unterscheiden, ob der Port offen oder gefiltert ist.

Deshalb zeigt nmap beim FIN-Scan oft den Zustand:

```text
open|filtered
```

Das bedeutet:

```text
Der Port ist entweder offen oder durch eine Firewall beziehungsweise Filterung nicht eindeutig bewertbar.
```

### Ergebnis für `10.153.210.192/26`

Gefunden wurden wieder 3 erreichbare Hosts:

```text
10.153.210.193
test4all.secp.lab.nm.ifi.lmu.de (10.153.210.251)
defaultgw.secp.lab.nm.ifi.lmu.de (10.153.210.254)
```

Die Ergebnisse waren:

```text
10.153.210.193                         22/tcp open|filtered ssh
10.153.210.251 test4all                 22/tcp open|filtered ssh
10.153.210.254 defaultgw                21/tcp open|filtered ftp
```

Interpretation:

- Beim normalen Scan wurden diese Ports als `open` erkannt.
- Beim FIN-Scan werden sie als `open|filtered` angezeigt.
- Das liegt daran, dass FIN-Scans nicht immer eindeutig erkennen können, ob ein Port wirklich offen ist oder ob keine Antwort wegen Filterung erfolgt.

Die Dienste passen trotzdem zu den vorherigen Ergebnissen:

```text
22/tcp ssh
21/tcp ftp
```

### Befehl für das eigene Subnetz

```bash
nmap -sF 10.153.210.0/29
```

### Sichtbares Ergebnis für `10.153.210.0/29`

In der kopierten Ausgabe sind folgende Hosts sichtbar:

```text
pcsec01.secp.lab.nm.ifi.lmu.de (10.153.210.1)
pcsec02.secp.lab.nm.ifi.lmu.de (10.153.210.2)
```

Die sichtbaren Ergebnisse waren:

```text
10.153.210.1 pcsec01                  22/tcp open|filtered ssh
10.153.210.2 pcsec02                  22/tcp open|filtered ssh
```

Interpretation:

- Im FIN-Scan wird Port 22 nicht als eindeutig `open`, sondern als `open|filtered` angezeigt.
- Das ist typisch für diese Scanart.
- Der normale Scan und der Portbereich-Scan haben bereits gezeigt, dass Port 22 auf den pcsec-Hosts offen ist.
- Beim FIN-Scan ist die Aussage ungenauer, weil fehlende Antworten nicht eindeutig interpretiert werden können.

Hinweis:

Im kopierten Output des FIN-Scans für das eigene Subnetz fehlt am Ende der vollständige Abschlussblock mit `Nmap done`. Falls die Abgabe die komplette Ausgabe verlangt, sollte dieser Scan noch einmal ausgeführt und bis zum Ende laufen gelassen werden:

```bash
nmap -sF 10.153.210.0/29
```

# Gesamtinterpretation

## Vorgegebenes Netz `10.153.210.192/26`

In diesem Netz wurden 3 Hosts gefunden:

| Host | Offener Port | Dienst | OS-Erkennung |
|---|---:|---|---|
| `10.153.210.193` | 22/tcp | SSH | Linux 3.x bis 4.x |
| `10.153.210.251` | 22/tcp | SSH | Linux 3.x bis 4.x |
| `10.153.210.254` | 21/tcp | FTP | Linux 3.x bis 4.x |

## Eigenes Subnetz `10.153.210.0/29`

In diesem Netz wurden 3 Hosts gefunden:

| Host | Offener Port | Dienst | OS-Erkennung |
|---|---:|---|---|
| `10.153.210.1` | 22/tcp | SSH | Linux 3.x bis 4.x |
| `10.153.210.2` | 22/tcp | SSH | Linux 3.x |
| `10.153.210.3` | 22/tcp | SSH | Linux 3.x bis 4.x |

## Vergleich der Scanarten

| Scanart | Befehl | Zweck | Ergebnis in dieser Aufgabe |
|---|---|---|---|
| Standardscan | `nmap <netz>` | Findet erreichbare Hosts und offene Standardports | SSH und FTP wurden gefunden |
| OS Detection | `nmap -O <netz>` | Versucht das Betriebssystem zu erkennen | Systeme wurden als Linux erkannt |
| Portbereich | `nmap -p 20-1000 <netz>` | Scannt nur Ports 20 bis 1000 | Gleiche offenen Dienste wurden gefunden |
| FIN-Scan | `nmap -sF <netz>` | Spezieller TCP-Scan mit FIN-Flag | Ports wurden als `open|filtered` angezeigt |

# Kurze Formulierung für die Abgabe

```text
Mit nmap wurden das vorgegebene Netz 10.153.210.192/26 und das eigene Subnetz 10.153.210.0/29 gescannt. Im vorgegebenen Netz wurden drei Hosts gefunden. Zwei davon hatten SSH auf Port 22 offen, ein Host hatte FTP auf Port 21 offen. Im eigenen Subnetz wurden ebenfalls drei Hosts gefunden, auf denen jeweils SSH auf Port 22 offen war.

Mit der Option -O wurde eine Betriebssystemerkennung durchgeführt. Nmap erkannte die Systeme als Linux-Systeme. Mit -p 20-1000 wurde der Scan auf die Ports 20 bis 1000 beschränkt. Dabei wurden dieselben offenen Dienste gefunden, da SSH und FTP in diesem Portbereich liegen. Mit -sF wurde ein FIN-Scan durchgeführt. Dabei wurden die Ports als open|filtered angezeigt, weil diese Scanart offene und gefilterte Ports nicht immer eindeutig unterscheiden kann.
```
