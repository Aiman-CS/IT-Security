# Aufgabe 11(g): CRL erstellen und Zertifikat widerrufen

## Ziel der Aufgabe

In Aufgabe 11(g) soll eine Certificate Revocation List, kurz CRL, erstellt werden.

Außerdem soll das Zertifikat aus Aufgabe 11(c) widerrufen werden.

Die CRL muss unter folgendem Pfad gespeichert werden:

```bash
/home/secpgast/Abgaben/11/crl.pem
```

Danach soll der CRL-Eintrag angezeigt werden.

---

## Was ist eine CRL?

CRL steht für:

```text
Certificate Revocation List
```

Auf Deutsch bedeutet das:

```text
Zertifikatswiderrufsliste
```

Eine CRL ist eine Liste von Zertifikaten, die von einer Certificate Authority, also CA, widerrufen wurden.

Ein Zertifikat kann widerrufen werden, obwohl es zeitlich eigentlich noch gültig wäre.

Zum Beispiel:

```text
Das Zertifikat wurde kompromittiert.
Der private Schlüssel wurde gestohlen.
Das Zertifikat wurde falsch ausgestellt.
Der Server oder Benutzer darf das Zertifikat nicht mehr verwenden.
```

Ein Zertifikat hat normalerweise ein Ablaufdatum. Ohne CRL würde ein Client nur prüfen, ob das Zertifikat zeitlich noch gültig ist und ob es von einer vertrauenswürdigen CA signiert wurde.

Mit einer CRL kann zusätzlich geprüft werden:

```text
Wurde dieses Zertifikat vorzeitig widerrufen?
```

Wenn das Zertifikat in der CRL steht, soll es nicht mehr akzeptiert werden.

---

## Warum machen wir das?

In Aufgabe 11(c) wurde ein Zertifikat für folgenden Host erstellt:

```text
pcsec1.secp.lab.nm.ifi.lmu.de
```

Dieses Zertifikat wurde von unserer eigenen CA signiert.

In Aufgabe 11(g) wird nun gezeigt, wie eine CA ein bereits ausgestelltes Zertifikat widerrufen kann.

Das ist ein wichtiger Teil einer Public Key Infrastructure, kurz PKI.

Eine CA muss nicht nur Zertifikate ausstellen können, sondern auch Zertifikate ungültig machen können.

---

## Wichtige Begriffe

## CA

CA steht für:

```text
Certificate Authority
```

Eine CA ist eine Zertifizierungsstelle.

Sie stellt Zertifikate aus und signiert sie mit ihrem privaten Schlüssel.

In dieser Aufgabe ist unsere eigene CA:

```text
LMU IFI SecP Gruppe 09 CA
```

Die CA-Dateien liegen unter anderem hier:

```bash
/home/secpgast/Abgaben/11/cacert.pem
/home/secpgast/Abgaben/11/private/cakey.pem
```

---

## Zertifikat

Ein Zertifikat verbindet eine Identität mit einem öffentlichen Schlüssel.

In Aufgabe 11(c) wurde ein Zertifikat für diesen Common Name erstellt:

```text
pcsec1.secp.lab.nm.ifi.lmu.de
```

Das Zertifikat liegt hier:

```bash
/home/secpgast/Abgaben/11/newcerts/11c.pem
```

---

## Private Key

Ein Private Key ist der geheime Schlüssel.

Für die CA liegt er hier:

```bash
/home/secpgast/Abgaben/11/private/cakey.pem
```

Mit diesem Schlüssel kann die CA Zertifikate signieren und Widerrufslisten erzeugen.

Der CA-Schlüssel muss geheim bleiben.

---

## Revocation

Revocation bedeutet:

```text
Widerruf
```

Wenn ein Zertifikat widerrufen wird, bleibt die Datei zwar technisch vorhanden, aber sie soll nicht mehr als gültig akzeptiert werden.

Der Widerruf wird in der CA-Datenbank und später in der CRL gespeichert.

---

## CRL-Datei

Die CRL-Datei ist die eigentliche Widerrufsliste.

In dieser Aufgabe soll sie hier gespeichert werden:

```bash
/home/secpgast/Abgaben/11/crl.pem
```

In dieser Datei steht, welche Zertifikate widerrufen wurden.

---

## Seriennummer

Jedes ausgestellte Zertifikat bekommt eine Seriennummer.

Die CRL speichert widerrufene Zertifikate nicht über ihren Dateinamen, sondern über ihre Seriennummer.

Deshalb ist die Seriennummer wichtig, um eindeutig zu erkennen, welches Zertifikat widerrufen wurde.

## Ausgangssituation

Wir befinden uns im Aufgabenverzeichnis:

```bash
cd /home/secpgast/Abgaben/11
```

Das Zertifikat aus Aufgabe 11(c) liegt hier:

```bash
newcerts/11c.pem
```

Die OpenSSL-Konfiguration liegt hier:


```bash
index.txt
serial
crlnumber
```

---

## Schritt 1: Zertifikat widerrufen

Befehl:

```bash
openssl ca \
  -config openssl.cnf \
  -revoke newcerts/11c.pem
```

---

## Erklärung des Befehls

## `openssl ca`

Dieser Befehl verwendet die CA-Funktionalität von OpenSSL.

Damit kann man Zertifikate signieren, widerrufen und CRLs erzeugen.

---

## `-config openssl.cnf`

Damit wird die CA-Konfiguration geladen.

In `openssl.cnf` stehen unter anderem:

```text
Pfad zum CA-Zertifikat
Pfad zum CA-Private-Key
Pfad zur CA-Datenbank
Pfad zur Seriennummer
Pfad zur CRL-Nummer
```

Ohne diese Konfigurationsdatei wüsste OpenSSL nicht, welche CA verwendet werden soll.

---

## `-revoke newcerts/11c.pem`

Damit wird das Zertifikat aus Aufgabe 11(c) widerrufen.

Das Zertifikat liegt hier:

```bash
/home/secpgast/Abgaben/11/newcerts/11c.pem
```

OpenSSL trägt den Widerruf in die CA-Datenbank `index.txt` ein.

---

## Warum muss der CA-Schlüssel verwendet werden?

Nur die CA, die ein Zertifikat ausgestellt hat, kann es korrekt widerrufen.

Deshalb muss OpenSSL beim Widerruf den privaten CA-Schlüssel verwenden:

```bash
/home/secpgast/Abgaben/11/private/cakey.pem
```

Wenn dieser Schlüssel passwortgeschützt ist, fragt OpenSSL nach dem Passwort.

---

## Erwartete Passwortabfrage

Beim Widerruf erscheint normalerweise:

```text
Enter pass phrase for /home/secpgast/Abgaben/11/private/cakey.pem:
```

Hier muss das Passwort des CA-Schlüssels eingegeben werden.

---

## Schritt 2: CRL erstellen

Befehl:

```bash
openssl ca \
  -config openssl.cnf \
  -gencrl \
  -out crl.pem
```

---

## Erklärung des Befehls

## `openssl ca`

Auch hier wird wieder die CA-Funktionalität von OpenSSL verwendet.

---

## `-config openssl.cnf`

Die CA-Konfiguration wird geladen.

Das ist wichtig, weil OpenSSL wissen muss, wo die CA-Datenbank und die CRL-Nummer liegen.

---

## `-gencrl`

Damit wird eine neue Certificate Revocation List erzeugt.

OpenSSL liest dafür die CA-Datenbank `index.txt` und sucht nach widerrufenen Zertifikaten.

Alle widerrufenen Zertifikate werden dann in die CRL geschrieben.

---

## `-out crl.pem`

Damit wird die CRL unter dem geforderten Dateinamen gespeichert:

```bash
/home/secpgast/Abgaben/11/crl.pem
```

---

## Schritt 3: Prüfen, ob die CRL-Datei existiert

Befehl:

```bash
ls -l crl.pem
```

Damit wird geprüft, ob die Datei erfolgreich erstellt wurde.

Erwartet wird, dass `crl.pem` im Aufgabenverzeichnis vorhanden ist.

---

## Schritt 4: CRL anzeigen

Befehl:

```bash
openssl crl \
  -in crl.pem \
  -noout \
  -text
```

---

## Erklärung des Befehls

## `openssl crl`

Dieser Befehl wird verwendet, um CRL-Dateien zu lesen und anzuzeigen.

---

## `-in crl.pem`

Damit wird die CRL-Datei als Eingabe verwendet.

---

## `-noout`

Damit wird verhindert, dass die CRL im rohen PEM-Format ausgegeben wird.

---

## `-text`

Damit wird die CRL in menschenlesbarer Form angezeigt.

Das ist wichtig, weil die Aufgabe verlangt, dass der CRL-Eintrag angezeigt wird.

---

## Nur den Widerrufseintrag anzeigen

Um nur den relevanten Teil der CRL zu sehen, kann man diesen Befehl verwenden:

```bash
openssl crl -in crl.pem -noout -text | grep -A 20 "Revoked Certificates"
```

Dieser Befehl zeigt den Abschnitt mit den widerrufenen Zertifikaten an.

---

## Erwarteter Inhalt der CRL

In der CRL sollte ein Abschnitt wie dieser erscheinen:

```text
Revoked Certificates:
    Serial Number: ...
        Revocation Date: ...
```

Die genaue Seriennummer hängt vom ausgestellten Zertifikat ab.

Wichtig ist, dass unter `Revoked Certificates` ein Eintrag für das widerrufene Zertifikat aus Aufgabe 11(c) erscheint.

---

## Schritt 5: Optional prüfen, ob das Zertifikat wirklich widerrufen ist

Befehl:

```bash
openssl verify \
  -crl_check \
  -CAfile cacert.pem \
  -CRLfile crl.pem \
  newcerts/11c.pem
```

---

## Erklärung des Prüfbefehls

## `openssl verify`

Dieser Befehl prüft ein Zertifikat gegen eine CA.

---

## `-crl_check`

Damit wird zusätzlich geprüft, ob das Zertifikat in der CRL steht.

---

## `-CAfile cacert.pem`

Damit wird das CA-Zertifikat angegeben, dem vertraut werden soll.

---

## `-CRLfile crl.pem`

Damit wird die CRL angegeben, die für die Widerrufsprüfung verwendet werden soll.

---

## `newcerts/11c.pem`

Das ist das Zertifikat aus Aufgabe 11(c), das geprüft werden soll.

---

## Erwartetes Ergebnis der optionalen Prüfung

Wenn der Widerruf funktioniert hat, ist eine Fehlermeldung wie diese korrekt:

```text
error 23 at 0 depth lookup: certificate revoked
```

Das ist in diesem Fall kein Problem, sondern genau das erwartete Ergebnis.

Es bedeutet:

```text
Das Zertifikat wurde erfolgreich widerrufen.
Die CRL enthält den Widerruf.
OpenSSL erkennt das Zertifikat als revoked.
```

---

## Wichtiger Hinweis zu widerrufenen Zertifikaten

Ein widerrufenes Zertifikat ist nicht automatisch aus dem Dateisystem gelöscht.

Die Datei bleibt weiterhin vorhanden:

```bash
newcerts/11c.pem
```

Der Unterschied ist:

```text
Vor dem Widerruf: Zertifikat wird als gültig akzeptiert
Nach dem Widerruf: Zertifikat steht in der CRL und soll nicht mehr akzeptiert werden
```
