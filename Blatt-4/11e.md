# Aufgabe 11(e): Zertifikat in PKCS#12 konvertieren

## Ziel der Aufgabe

In Aufgabe 11(e) soll das in Aufgabe 11(c) erstellte Zertifikat in das PKCS#12-Format konvertiert werden.

Die Ausgabedatei muss unter folgendem Pfad gespeichert werden:

```bash
/home/secpgast/Abgaben/11/newcerts/11c.pkcs12
```

Das Passwort für die neue PKCS#12-Datei muss lauten:

```text
SecPCert
```

---

## Warum machen wir das?

In Aufgabe 11(c) wurden zwei wichtige Dateien erstellt:

```bash
/home/secpgast/Abgaben/11/keys/11c.key
/home/secpgast/Abgaben/11/newcerts/11c.pem
```

Dabei ist:

```text
keys/11c.key: der private Schlüssel
newcerts/11c.pem: das von der eigenen CA signierte Zertifikat
cacert.pem: das Zertifikat der eigenen CA
```

Das PKCS#12-Format wird verwendet, um Zertifikat, privaten Schlüssel und optional die CA-Zertifikatskette in einer einzigen Datei zu speichern.

Das ist praktisch, weil viele Programme, Browser und Betriebssysteme PKCS#12-Dateien importieren können.

Eine PKCS#12-Datei hat häufig die Endung:

```text
.p12
.pfx
.pkcs12
```

In dieser Aufgabe wird die Datei mit der Endung `.pkcs12` gespeichert.

---

## Arbeitsverzeichnis

Zuerst wechseln wir in das Aufgabenverzeichnis:

```bash
cd /home/secpgast/Abgaben/11
```

Damit können alle Pfade relativ zum Aufgabenverzeichnis verwendet werden.

---

## PKCS#12-Datei erzeugen

Befehl:

```bash
openssl pkcs12 \
  -export \
  -inkey keys/11c.key \
  -in newcerts/11c.pem \
  -certfile cacert.pem \
  -out newcerts/11c.pkcs12 \
  -name "pcsec1.secp.lab.nm.ifi.lmu.de" \
  -passout pass:SecPCert
```

---

## Erklärung des Befehls

### `openssl pkcs12`

Dieser OpenSSL-Befehl wird verwendet, um PKCS#12-Dateien zu erstellen, zu lesen oder zu prüfen.

In dieser Aufgabe wird er verwendet, um eine neue PKCS#12-Datei zu erzeugen.

---

### `-export`

Mit `-export` wird OpenSSL gesagt, dass eine neue PKCS#12-Datei exportiert werden soll.

Ohne diese Option würde OpenSSL eher versuchen, eine vorhandene PKCS#12-Datei zu lesen.

---

### `-inkey keys/11c.key`

Damit wird der private Schlüssel angegeben, der in die PKCS#12-Datei aufgenommen werden soll.

Der private Schlüssel wurde in Aufgabe 11(c) erstellt und liegt hier:

```bash
/home/secpgast/Abgaben/11/keys/11c.key
```

Dieser Schlüssel ist mit DES3 verschlüsselt. Deshalb fragt OpenSSL beim Ausführen des Befehls nach dem Passwort dieses Schlüssels.

Wichtig:

```text
Das Passwort für keys/11c.key ist das Passwort, das beim Erzeugen des DES3-Schlüssels vergeben wurde.
Das Passwort SecPCert ist das neue Passwort für die PKCS#12-Datei.
```

---

### `-in newcerts/11c.pem`

Damit wird das Zertifikat angegeben, das in die PKCS#12-Datei aufgenommen werden soll.

Dieses Zertifikat wurde in Aufgabe 11(c) von der eigenen CA signiert.

Pfad:

```bash
/home/secpgast/Abgaben/11/newcerts/11c.pem
```

---

### `-certfile cacert.pem`

Damit wird zusätzlich das CA-Zertifikat in die PKCS#12-Datei aufgenommen.

Pfad:

```bash
/home/secpgast/Abgaben/11/cacert.pem
```

Das ist sinnvoll, weil dadurch nicht nur das einzelne Zertifikat, sondern auch die dazugehörige ausstellende CA mitgegeben wird.

Dadurch kann ein importierendes Programm erkennen, von welcher CA das Zertifikat ausgestellt wurde.

---

### `-out newcerts/11c.pkcs12`

Damit wird die Ausgabedatei festgelegt.

Die Aufgabe verlangt genau diesen Speicherort:

```bash
/home/secpgast/Abgaben/11/newcerts/11c.pkcs12
```

---

### `-name "pcsec1.secp.lab.nm.ifi.lmu.de"`

Damit wird ein Anzeigename für den Eintrag innerhalb der PKCS#12-Datei gesetzt.

Hier wurde der Common Name aus Aufgabe 11(c) verwendet:

```text
pcsec1.secp.lab.nm.ifi.lmu.de
```

Das macht die Datei später leichter verständlich, wenn sie in einem Browser oder Zertifikatsspeicher angezeigt wird.

---

### `-passout pass:SecPCert`

Damit wird das Passwort für die neu erzeugte PKCS#12-Datei gesetzt.

Die Aufgabe verlangt ausdrücklich dieses Passwort:

```text
SecPCert
```

Deshalb wird es direkt mit `-passout pass:SecPCert` gesetzt.

---

## Erwartete Passwortabfrage

Beim Ausführen des Befehls fragt OpenSSL nach dem Passwort des privaten Schlüssels:

```text
Enter pass phrase for keys/11c.key:
```

Hier muss das Passwort eingegeben werden, das beim Erstellen von `keys/11c.key` in Aufgabe 11(c) gesetzt wurde.

Das ist nicht zwingend dasselbe Passwort wie `SecPCert`.

---

## Datei prüfen

Nach der Konvertierung kann geprüft werden, ob die Datei erstellt wurde:

```bash
ls -l newcerts/11c.pkcs12
```

Erwartetes Ergebnis:

```text
newcerts/11c.pkcs12
```

Die Datei sollte existieren und eine Größe größer als 0 Byte haben.

---

## PKCS#12-Datei öffnen und prüfen

Befehl:

```bash
openssl pkcs12 \
  -in newcerts/11c.pkcs12 \
  -noout \
  -info \
  -passin pass:SecPCert
```

---

## Erklärung des Prüfbefehls

### `-in newcerts/11c.pkcs12`

Damit wird die neu erstellte PKCS#12-Datei als Eingabe verwendet.

### `-noout`

Damit wird verhindert, dass der private Schlüssel oder Zertifikatsinhalt vollständig ausgegeben wird.

Das ist wichtig, weil private Schlüssel nicht unnötig im Terminal angezeigt werden sollten.

### `-info`

Damit zeigt OpenSSL Informationen über den Inhalt der PKCS#12-Datei an.

### `-passin pass:SecPCert`

Damit wird das Passwort verwendet, das laut Aufgabe für die neue PKCS#12-Datei gesetzt werden sollte.

Wenn dieser Befehl ohne Passwortfehler funktioniert, wurde das Passwort korrekt gesetzt.

---

## Warum wurde nicht nur das Zertifikat konvertiert?

Eine PKCS#12-Datei enthält typischerweise nicht nur ein Zertifikat, sondern auch den dazugehörigen privaten Schlüssel.

Deshalb wurden diese Dateien zusammen exportiert:

```text
Privater Schlüssel: keys/11c.key
Zertifikat: newcerts/11c.pem
CA-Zertifikat: cacert.pem
```

Damit enthält `11c.pkcs12` alles, was für den Import des Zertifikats mit privatem Schlüssel nötig ist.
