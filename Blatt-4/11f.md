# Aufgabe 11(f): Passwort aus dem privaten Schlüssel entfernen

## Ziel der Aufgabe

In Aufgabe 11(f) soll das Passwort aus dem privaten Schlüssel entfernt werden.

Der ursprüngliche private Schlüssel aus Aufgabe 11(c) liegt hier:

```bash
/home/secpgast/Abgaben/11/keys/11c.key
```

Dieser Schlüssel ist mit DES3 verschlüsselt und dadurch durch ein Passwort geschützt.

Die neue unverschlüsselte Version soll unter folgendem Pfad gespeichert werden:

```bash
/home/secpgast/Abgaben/11/keys/11c.key.insecure
```

---

## Warum machen wir das?

In Aufgabe 11(c) wurde der private Schlüssel mit DES3 verschlüsselt erstellt.

Das bedeutet, dass jedes Programm beim Verwenden des Schlüssels zuerst das Passwort abfragen muss.

Für manche Serverdienste oder automatisierte Prozesse ist das unpraktisch, weil der Dienst nach einem Neustart nicht automatisch starten kann, wenn ein Passwort manuell eingegeben werden muss.

Deshalb wird hier eine zweite Version des Schlüssels erstellt, bei der das Passwort entfernt wurde.

Wichtig: Diese Datei heißt bewusst `insecure`, weil sie unsicherer ist als der verschlüsselte Schlüssel.

---

## Sicherheitsunterschied

### Verschlüsselter Schlüssel

Der ursprüngliche Schlüssel:

```bash
keys/11c.key
```

ist mit DES3 verschlüsselt.

Das bedeutet:

```text
Ein Angreifer braucht nicht nur die Datei, sondern auch das Passwort.
```

### Unverschlüsselter Schlüssel

Der neue Schlüssel:

```bash
keys/11c.key.insecure
```

ist nicht mehr mit einem Passwort geschützt.

Das bedeutet:

```text
Wer Zugriff auf diese Datei hat, kann den privaten Schlüssel direkt verwenden.
```

Deshalb sollte diese Datei besonders geschützt werden.

---

## Arbeitsverzeichnis

Zuerst wird in das Aufgabenverzeichnis gewechselt:

```bash
cd /home/secpgast/Abgaben/11
```

Damit können die Pfade relativ zum Aufgabenverzeichnis angegeben werden.

---

## Passwort aus dem Schlüssel entfernen

Befehl:

```bash
openssl rsa \
  -in keys/11c.key \
  -out keys/11c.key.insecure
```

---

## Erklärung des Befehls

### `openssl rsa`

Dieser OpenSSL-Befehl wird verwendet, um RSA-Schlüssel zu lesen, zu prüfen oder in einer anderen Form auszugeben.

In dieser Aufgabe wird er verwendet, um den verschlüsselten privaten RSA-Schlüssel einzulesen und ohne Passwort wieder auszugeben.

---

### `-in keys/11c.key`

Damit wird der ursprüngliche private Schlüssel als Eingabedatei angegeben.

Dieser Schlüssel wurde in Aufgabe 11(c) erstellt:

```bash
/home/secpgast/Abgaben/11/keys/11c.key
```

Er ist mit DES3 verschlüsselt und deshalb passwortgeschützt.

---

### `-out keys/11c.key.insecure`

Damit wird die neue unverschlüsselte Version des Schlüssels gespeichert.

Die Aufgabe verlangt genau diesen Pfad:

```bash
/home/secpgast/Abgaben/11/keys/11c.key.insecure
```

---

## Passwortabfrage

Beim Ausführen des Befehls fragt OpenSSL nach dem Passwort des ursprünglichen Schlüssels:

```text
Enter pass phrase for keys/11c.key:
```

Hier muss das Passwort eingegeben werden, das beim Erstellen von `keys/11c.key` in Aufgabe 11(c) vergeben wurde.

Danach schreibt OpenSSL den privaten Schlüssel ohne Passwortschutz in die neue Datei.

---

## Dateirechte setzen

Befehl:

```bash
chmod 600 keys/11c.key.insecure
```

---

## Warum setzen wir `chmod 600`?

Die neue Datei enthält den privaten Schlüssel ohne Passwortschutz.

Deshalb sollte nur der Besitzer der Datei Zugriff darauf haben.

`chmod 600` bedeutet:

```text
Besitzer: lesen und schreiben
Gruppe: kein Zugriff
Andere Benutzer: kein Zugriff
```

Das reduziert das Risiko, dass andere Benutzer auf dem System den privaten Schlüssel lesen können.

---

## Prüfen, ob die Datei existiert

Befehl:

```bash
ls -l keys/11c.key keys/11c.key.insecure
```

Damit wird geprüft, ob sowohl der ursprüngliche verschlüsselte Schlüssel als auch die neue unverschlüsselte Version vorhanden sind.

Erwartete Dateien:

```text
keys/11c.key
keys/11c.key.insecure
```

---

## Prüfen, ob der neue Schlüssel gültig ist

Befehl:

```bash
openssl rsa -in keys/11c.key.insecure -check -noout
```

---

## Erklärung des Prüfbefehls

### `-in keys/11c.key.insecure`

Damit wird der neue unverschlüsselte Schlüssel geprüft.

### `-check`

Damit prüft OpenSSL, ob der RSA-Schlüssel mathematisch korrekt ist.

### `-noout`

Damit wird der Schlüssel selbst nicht im Terminal ausgegeben.

Das ist wichtig, weil private Schlüssel nicht unnötig angezeigt oder kopiert werden sollten.

---

## Erwartetes Ergebnis

Wenn der Schlüssel korrekt ist, erscheint:

```text
RSA key ok
```

Wichtig ist auch: Bei diesem Befehl sollte keine Passwortabfrage mehr erscheinen.

Das zeigt, dass das Passwort erfolgreich entfernt wurde.

---

## Unterschied zwischen den beiden Schlüsseldateien prüfen

Optional kann man die ersten Zeilen beider Dateien vergleichen:

```bash
head -n 5 keys/11c.key
head -n 5 keys/11c.key.insecure
```

Beim ursprünglichen Schlüssel sollte sichtbar sein, dass er verschlüsselt ist:

```text
-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,...
```

Beim neuen Schlüssel sollte kein `ENCRYPTED` mehr stehen.

Das zeigt, dass der neue Schlüssel unverschlüsselt ist.

---

## Warum heißt die Datei `11c.key.insecure`?

Der Name `insecure` macht deutlich, dass diese Version des Schlüssels weniger sicher ist.

Der Schlüssel ist zwar technisch funktionsfähig, aber er ist nicht mehr durch ein Passwort geschützt.

Wenn jemand diese Datei lesen kann, kann er den privaten Schlüssel direkt verwenden.

Deshalb ist der Dateiname passend und entspricht der Aufgabenstellung.
