## 1. OpenSSL installation problem and fix

At first, OpenSSL was not installed:

```bash
openssl version
```

Output:

```bash
-bash: openssl: command not found
```

Trying to install OpenSSL initially failed because the VM could not resolve `archive.debian.org`:

```bash
apt install openssl -y
```

Output:

```bash
Temporary failure resolving 'archive.debian.org'
E: Unable to fetch some archives, maybe run apt-get update or try with --fix-missing?
```

The reason was that `pcsec1` had no working default IPv6 route. The VM had IPv6 on interface `ens2`:

```bash
ip addr
```

Relevant output:

```bash
2: ens2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP group default qlen 1000
    inet6 2001:db6::3/64 scope global
```

The IPv6 gateway was visible in the neighbor table:

```bash
ip neigh
```

Relevant output:

```bash
2001:db6::ff dev ens2 lladdr fe:54:00:11:8e:3c router REACHABLE
```

The IPv6 default route was added with:

```bash
ip -6 route add default via 2001:db6::ff dev ens2
```

After that, IPv6 connectivity worked:

```bash
ping6 -c 2 2001:db6::ff
```

Output:

```bash
PING 2001:db6::ff(2001:db6::ff) 56 data bytes
64 bytes from 2001:db6::ff: icmp_seq=1 ttl=64 time=0.854 ms
64 bytes from 2001:db6::ff: icmp_seq=2 ttl=64 time=0.753 ms

--- 2001:db6::ff ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1002ms
```

DNS also worked over IPv6:

```bash
ping6 -c 2 archive.debian.org
```

Output:

```bash
PING archive.debian.org(2a04:4e42:200::644 (2a04:4e42:200::644)) 56 data bytes
64 bytes from 2a04:4e42:200::644 (2a04:4e42:200::644): icmp_seq=1 ttl=57 time=10.4 ms
```

OpenSSL was then installed by forcing apt to use IPv6:

```bash
apt -o Acquire::ForceIPv6=true update
apt -o Acquire::ForceIPv6=true install openssl -y
```

## 2. Creating the directory structure

The required base directory was:

```bash
BASE=/home/secpgast/Abgaben/11
```

The required directories and OpenSSL database files were created with:

```bash
mkdir -p $BASE/keys $BASE/private $BASE/newcerts
chmod 700 $BASE/private

touch $BASE/index.txt
echo 1000 > $BASE/serial
echo 1000 > $BASE/crlnumber
```

Explanation:

- `keys/` is used for generated private keys later in the assignment.
- `private/` stores the CA private key.
- `newcerts/` stores issued certificates.
- `index.txt` is the OpenSSL CA certificate database.
- `serial` stores the next certificate serial number.
- `crlnumber` is needed later for certificate revocation lists.

The OpenSSL configuration file was created at:

Important certificate subject values used:

```text
Country Name: DE

Organization Name: LMU IFI SecP Gruppe 09
Common Name: LMU IFI SecP Gruppe 09 CA
Email Address: mana.jaqoubi@campus.lmu.de
```

The configuration included a CA extension section similar to this:

```ini
[ v3_ca ]
subjectKeyIdentifier   = hash
authorityKeyIdentifier = keyid:always,issuer
basicConstraints       = critical, CA:true
keyUsage               = critical, keyCertSign, cRLSign
```

Explanation:

- `basicConstraints = CA:true` marks the certificate as a CA certificate.
- `keyCertSign` allows the CA certificate to sign other certificates.
- `cRLSign` allows the CA to sign certificate revocation lists.

## 4. Creating the AES256-encrypted CA private key

The first attempt used:

```bash
openssl req \
  -config openssl.cnf \
  -new \
  -x509 \
  -days 3650 \
  -newkey rsa:2048 \
  -aes256 \
  -extensions v3_ca \
  -keyout private/cakey.pem \
  -out cacert.pem
```

This failed with:

```bash
req: Unknown digest aes256
req: Use -help for summary.
```

Therefore, the key and certificate were generated in two separate steps.

First, the AES256-encrypted 2048-bit RSA private key was created:

```bash
cd /home/secpgast/Abgaben/11
rm -f private/cakey.pem cacert.pem

openssl genrsa -aes256 -out private/cakey.pem 2048
```

Output:

```bash
Generating RSA private key, 2048 bit long modulus
.+++++
..........................+++++
e is 65537 (0x010001)
Enter pass phrase for private/cakey.pem:
Verifying - Enter pass phrase for private/cakey.pem:
```

Result:

```bash
/home/secpgast/Abgaben/11/private/cakey.pem
```

The actual private key content is intentionally not included in this documentation, because private keys should not be copied into reports or shared unnecessarily.

## 5. Creating the self-signed CA certificate

The self-signed CA certificate was created from the encrypted CA private key:

```bash
openssl req \
  -config openssl.cnf \
  -new \
  -x509 \
  -days 3650 \
  -key private/cakey.pem \
  -extensions v3_ca \
  -out cacert.pem
```

Output:

```bash
Enter pass phrase for private/cakey.pem:
```

Result:

```bash
/home/secpgast/Abgaben/11/cacert.pem
```

## 6. Verification of the CA certificate

The certificate was checked with:

```bash
openssl x509 -in cacert.pem -noout -subject -issuer -dates
```

Output:

```bash
subject=C = DE, ST = Bavaria, L = Munich, O = LMU IFI SecP Gruppe 09, CN = LMU IFI SecP Gruppe 09 CA, emailAddress = mana.jaqoubi@campus.lmu.de
issuer=C = DE, ST = Bavaria, L = Munich, O = LMU IFI SecP Gruppe 09, CN = LMU IFI SecP Gruppe 09 CA, emailAddress = mana.jaqoubi@campus.lmu.de
notBefore=May 18 08:56:34 2026 GMT
notAfter=May 15 08:56:34 2036 GMT
```

Explanation:

- The `subject` and `issuer` are identical, which confirms that this is a self-signed CA certificate.
- The certificate starts on `May 18 2026`.
- The certificate expires on `May 15 2036`, so it is valid for approximately 10 years.
